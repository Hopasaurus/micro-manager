# T-0146 — When saving after edit return to board

The URL stays on the item when saving after edit the system should navigate to
the board.

## What was wrong

Saving an edit in the item panel (`hx-patch /p/:id/items/:itemId`) swapped in
the board and dismissed the panel, but the address bar stayed on
`/p/:id/item/:itemId`. Reloading that URI re-opened the panel over the new
state — the address named a view that was no longer on screen
(spec-gui.md §4.1 rule 1: the URI names the view).

## Fix

`afterMutation` (internal/web/item.go) is the ONE place every dismissing
mutation renders — edit save, add, remove, and all panel/dialog actions — so
it now sets `HX-Replace-Url: /p/<projectId>/board` on the response. htmx
updates the address bar to the board, which the swap already showed.

`HX-Replace-Url` rather than `HX-Push-Url`: the panel URL is a transient
editing state, not a destination, and a mutation launched from the board
itself (card menu, drag) must not stack a duplicate history entry per action.

`afterMutationAddAnother` ("Save and add another", T-0080) deliberately does
NOT get the header: the fresh panel stays open, and the board URL would lie
about what is on screen.

## Test

`TestMutationReturnsToTheBoardURL` (internal/web/item_test.go):
- PATCH edit carries `HX-Replace-Url: /p/<id>/board`;
- a panel action (move) carries it too, proving the fix is central;
- addAnother carries no such header.
