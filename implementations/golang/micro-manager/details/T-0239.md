# T-0239 — Research effort to make column collapsing generic to all columns

Report saved to `project/research-column-collapse.md`.

## Notes

**2026-08-21** — Traced the collapse mechanism end to end: CSS
(`mm.css`'s `[data-collapsed="true"]` rules) and the T-0152 drag/drop
handling in `mm.js` are already fully generic; only the state population
(`board.go`'s `somedayCollapsed`), the template gates (`board.html`), the
client encoding (`mm.js`'s single boolean/header/localStorage-key), and
the config field (`mm/config.go`'s `ShowSomeday bool`, which predates
spec-gui.md §9.3's rename to `collapsedStages`) are hard-coded to the
literal stage `someday`. Confirmed this is a scoping gap, not a spec
violation — `TestAuditTestids`'s instance table already pins
`board-column-<slug>-toggle` to exactly one required instance today,
matching spec-gui.md §5.5's own "every column or only some" wording.

Resolved the one real open question: how the client should encode a *set*
of collapsed stages once it's no longer a single flag. Recommended a
comma-separated list (`X-Collapsed-Stages` header,
`mm:collapsed-stages:<project>` localStorage key), matching this
codebase's existing comma-list convention for `tags:`, over a JSON
encoding or one header per stage (the latter would couple the client to a
directory's own declared stage list, which the generalization is meant to
avoid). Also confirmed the project-config default
(`ui.board.collapsedStages`) and the live per-request header are
complementary — the same relationship version 1's `showSomeday` boolean
already had — not a design tension needing a decision.

Spawned T-0240 for the implementation, which is small and fully
mechanical given the above: extend the existing per-column loop in
`board.go`/`board.html`, generalize the four hard-coded spots in `mm.js`,
rename/generalize the config field (no shipped config in this repository
sets `ui.board.showSomeday`, so there is no real migration burden), and
extend the small set of tests that assert the current someday-only shape.

Report saved to project/research-column-collapse.md; found the CSS and drag/drop layers are already generic, resolved the client-encoding design question, and spawned T-0240 for the (mechanical) implementation.
