# T-0024 — Implement period resolution and report building

## Context

`spec-tools.md` §5.1.11. The report is the artifact people paste elsewhere, so
the human output must be paste-ready markdown — no box drawing, no colour when
redirected.

## Requirements

- Token vocabulary: `last-week`, `this-week`, `YYYY-Www`, `last-N-days`, `all`
  are MUST; month forms SHOULD.
- Precedence: `--since`/`--until`, then `--week`, then `--period`/`--last-week`/
  `--this-week`, then `MM_REPORT_PERIOD`, then the default `last-week`.
- The wrapper resolves the environment variable; `Store.report` receives a fully
  resolved period with no notion that a default was applied.
- An unparseable `MM_REPORT_PERIOD` is a usage error naming the variable. Never
  fall back silently — a typo in a shell profile would otherwise change every
  report the user ever runs.
- Output must state the resolved period and its source.
- Matching is date-granular against `done:`. Do not invent finer resolution.
- Warn when the requested period predates the oldest month group present in
  `done.md`, since archived months are invisible without `--include-archives`.

## The trap

ISO-8601 week arithmetic, not "seven days back". Weeks start Monday, and the
ISO week-year diverges from the calendar year at both ends. Use a tested
implementation and add cases for the year-boundary weeks; hand-rolled week math
is wrong more often than not.

> **Correction.** This section previously claimed 2026-12-28 is in week 1 of ISO
> year 2027. It is not: 2026 is a 53-week year, so 2026-12-28 is the Monday of
> **2026-W53**, and that week runs to 2027-01-03. Real examples of the
> divergence are 2025-12-29, which is in 2026-W01, and 2027-01-03, which is in
> 2026-W53. The point stands; the example did not, and it was load-bearing —
> a test written from it would have asserted the wrong answer.

The second half of the trap: **a week number is not a range check.** Week 53
exists only in long ISO years, so `2027-W53` must be rejected while `2026-W53`
is accepted. The implementation verifies a computed week by asking for its own
week number back and comparing.
