# T-0128 — Vendor idiomorph.js for morphing swaps (pin version, record licence)

## Context

`research-app-fllicker.md` §3 A: the biggest flicker fix available is morphing —
diff the old and new DOM and apply only the changes, so a no-op refresh changes
nothing on screen and hover, focus, and scroll survive real ones.

The vendored `static/htmx.min.js` (2.0.7) contains **no morph support** (verified
during the spike: no morph symbols in the file). htmx 2.x reads
`hx-swap="morph"` and uses the `Idiomorph` global when present, falling back to
the plain swap when it is not — so this item is purely the enabler: get
idiomorph into the page, pinned and recorded, exactly the way htmx itself was
(session-003 §4: ask first, pin the version, record the licence).

## Findings (verified against primary sources, 2026-08-02)

- Morphing in the htmx 2.x line is **via extensions** — the htmx docs say so
explicitly, and vendored htmx 2.0.7 has zero morph references in core.
- The idiomorph npm package (latest **0.7.4**, Zero-Clause BSD — verified in the
tarball's LICENSE) ships `dist/idiomorph-ext.min.js`: **one file** that bundles
the Idiomorph library (`var Idiomorph = …`) and registers the htmx `morph`
extension (`defineExtension("morph", …)`, `Idiomorph.morph(target, fragment)`).
  No separate `idiomorph.min.js` is needed.
- htmx 2.0.7 swap dispatch: an unhandled swap style falls back to the default
  swap style (`innerHTML`). So `hx-swap="morph"` without the extension active on
  the element is *not* degradation-safe — it silently becomes an `innerHTML`
  swap, which leaves the section's own `data-*` attributes stale. The
  `hx-ext="morph"` wiring must therefore land with the swap-verb change in
  T-0129, and the guard test below asserts the vendored file really is the
  extension build.

## Requirements

- Ask before adding the file to the repository (the session-003 rule — this is
  the third third-party JavaScript in the project). **Asked and answered: the
  work was instructed.**
- Vendor `idiomorph-ext.min.js` 0.7.4 into `internal/web/static/`, covered by
  the existing `embed.FS` so the binary stays self-contained.
- Pin the version and record licence + provenance in `architecture.md` §3's
  dependency table, alongside htmx and `htmx-ext-sse`: idiomorph-ext 0.7.4,
  0BSD (verified from the shipped LICENSE).
- Load it after htmx core and after `htmx-ext-sse.js`, before `mm.js` —
  `mm.js` issues `htmx.ajax()` swaps, and a swap that runs before the morph
  extension is registered would not morph.
- The test `TestVendoredScriptsAreServed` asserts the file is served, loads in
  the right position, and really registers the `morph` extension.
- Nothing else: the `hx-ext="morph"` wiring and the swap-verb change are
  T-0129.
