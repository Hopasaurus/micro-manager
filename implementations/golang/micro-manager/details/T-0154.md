# T-0154 — CLI: reject --init --slots 0 and --slot-width 0

Finding F2 in `project/code-review-007.md`.

`runInit` (internal/cli/run.go:128-141) explicitly rejects `--id-width 0`
("Zero is the library's 'not given' value, so it must never reach Init as an
explicit request") but applies no such guard to `--slots` or `--slot-width`.
`mm/init.go:67-68` treats `wip == 0` as "use 1" and `width == 0` as "use 2",
so:

```
$ mm --init --project Zero --slots 0
created .../micro-manager for Zero    # one slot, claimed as success
```

A user typing `--slots 0` gets a one-slot directory and a success message.

Fix: mirror the `--id-width` guard — `--slots N` and `--slot-width N` with
`N < 1` are usage errors with a clear message. `--wip 0` is already handled by
the library with a clear message, so only `--init` needs the CLI-side guard.

Verify: extend `TestInitRejectsBadGrammarFlags` (grammar_test.go) with
`--slots 0`, `--slot-width 0`, `--slots -1`, `--slot-width -1`; all must exit
2. `go -C implementations/golang test ./internal/cli/`.
