# T-0054 — Build the httptest harness for the web layer

## Context

Every view item from here on is expected to arrive with tests. A harness written
after the views is a harness written to fit what was built, so this one came
first — before the board, before the item panel, before anything that would
otherwise decide its shape.

## As built

`internal/web/harness_test.go` and `logger_test.go`.

**Requests go through `http.Handler`, not a socket.** `httptest` needs no port,
cannot collide with a service the user already has running on 7717, and leaves
nothing behind when a test fails. The two exceptions are the tests for `Start`
and the Unix socket, where binding is the behaviour under test.

**The harness sets a valid `Host` for every request.** Otherwise every test in
the package would have to remember to, and would eventually fail with a 421 for
a reason that has nothing to do with what it was checking. The Host guard's own
tests set it explicitly.

**Fixtures are copied, never used in place.** `testdata/` is read-only by
convention and later items mutate directories. A test asserts the served path is
not inside the corpus, so a future shortcut is caught rather than corrupting the
corpus for every test that runs after it.

**Failures print the body.** `expectStatus` fails with the response attached: a
bare "want 200, got 500" sends the reader to a terminal to reproduce it by hand.

**The service's logger writes to `t.Log`.** A configuration warning or a remote
access banner raised during a test is attached to that test rather than
scrolling past, and a test that wants to assert on one can.

## The assertion style

Chained and small: `ts.get(path).expectStatus(200).json(&body)`. `expectHeader`
takes a substring rather than a whole value, because CSP is one long header and
every assertion about it is about a single directive.
