# T-0254 — Style the audit log viewer

T-0253's `/p/:id/audit` page shipped with zero styling: a bare `<table>`,
default browser borders, no visual relationship to the rest of the app.

## Fix

- `internal/web/templates/audit.html`: rows changed from `<table>`/`<tr>`/
  `<td>` to styled divs, matching `report-item`/`check-violation` — the
  idiom every other list view in this build already uses. `data-testid`
  and the `data-item-id`/`data-field` attributes are unchanged (spec-gui.md
  §5.1: only those are normative, never tag names), so no test needed to
  change on that account.
  - Header gained an entry-count badge (mirroring `report-group-count`).
  - Each row: a monospace timestamp, the item ID as a link into its own
    panel (`/p/:id/item/:id`), the field name as a small pill, and the
    value — a blank value (a detail-file touch, a removal) renders an em
    dash rather than an empty cell.
  - A `removed` row's field pill switches to the danger feedback color, the
    one place this list needed color as well as text to read at a glance
    (§11 rule 2 still holds: the word "removed" is there regardless).
- `internal/web/static/mm.css`: new `.mm-audit` block reusing existing
  design tokens only (`--mm-space-*`, `--mm-color-fg-muted`,
  `--mm-color-accent-base`, `--mm-color-feedback-danger`, etc.) — no new
  tokens. Also added a small `.mm-link` utility class, since
  `settings-audit-view` (T-0253) already referenced that class name with
  nothing backing it.
- `internal/web/templates/settings.html`: the audit toggle's checkbox now
  uses `mm-field--inline` (the same class `report-include-wip` uses) so it
  sits inline with its label instead of stacking.
- `spec-gui.md` §5.11: updated the illustrative markup from `<table>` to
  divs, with a note that tag names are illustrative, not normative.

## Tests

No new tests — this is a styling-only change; the same testids and
`data-*` attributes are asserted by T-0253's existing suite
(`TestAuditViewListsEntriesNewestFirst` et al.), which stayed green
unmodified.

Verified live in a running browser, light and dark themes both: count
badge, monospace timestamps, field pills, item-ID links resolving to the
correct item panel, and a blank value rendering as "—" rather than an
empty cell.

`go build`, `go vet`, `gofmt -l`, and the full `go test ./...` are all
green.

## Notes

Restyled the audit log page (row list instead of a bare table, entry count, item links, blank-value handling) matching the rest of the app's design tokens.
