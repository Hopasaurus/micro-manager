# T-0265 — Phase 1: detect external changes in the open item panel

## Context

Follow-up from T-0261. The project fingerprint notices both board and detail changes, but the open item panel neither listens nor carries an item-specific revision. It can remain stale while the board behind it refreshes.

## Requirements

- Add an opaque content-based item revision covering the full item line and exact detail-file state.
- Render the baseline revision on existing-item panels.
- Extend project change notification with an item-panel wake-up signal; retain SSE-down polling behavior.
- Add an item-specific freshness probe so unrelated project changes do not disturb the form.
- When the form is clean and its item changed, preserve the form, notify accessibly, and offer an explicit reload. Do not auto-reload or steal focus.
- Treat any local input as dirty and never replace it; full dirty conflict handling belongs to phase 2.
- Handle moved/finished, removed, and temporarily unreadable items explicitly.
- Do not revive per-column file-diff work; use the coarse broker signal plus targeted item comparison.

## Verification

Cover board-only changes, detail-only changes, no-op/unrelated changes, SSE and SSE-down polling, repeated events, removal, focus preservation, and clean explicit reload.

## Reference

T-0261 contains the vetted revision/event design and UX state model.
