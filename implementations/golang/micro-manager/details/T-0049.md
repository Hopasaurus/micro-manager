# T-0049 — Scaffold cmd/mm-ui, internal/web and the Echo v5 dependency

## As built

`cmd/mm-ui/main.go`, `internal/web/{server,routes,assets,version}.go`,
`internal/web/static/`. Echo pinned at v5.3.1.

`go run ./cmd/mm-ui` starts, serves `GET /api/v1/health` and `/static/*`, and
refuses a non-loopback bind. Tests arrive with **T-0054**, the harness item that
follows this one — deliberately, because a harness written after the views is a
harness written to fit what was built.

## What the v5 API actually looks like

Verified against the module in the cache, not from memory
(`project/architecture-echo-v5.md` §7 asks for exactly this):

- `echo.HandlerFunc` is `func(c *echo.Context) error` — `Context` is a concrete
  struct and the parameter is a pointer, so no v4 handler signature compiles.
- **`HideBanner` and `HidePort` are not fields on `Echo`.** They exist only on
  `StartConfig`. The architecture notes imply otherwise by omission.
- `StartConfig` carries `BeforeServeFunc`, which is where `WriteTimeout = 0` is
  set — required for the event stream of §2.3, and a setting whose absence looks
  like a flaky client rather than a misconfiguration.
- `ListenerAddrFunc` is how a test learns the real port after binding `:0`.

## Decisions

**One place reads the world.** `cmd/mm-ui/main.go` is the only file in the
service that touches argv, the environment or the working directory; everything
below it receives values. That is the same rule the library follows and for the
same reason — a service outlives the shell that started it.

**Only implemented routes are registered.** A route wired to a "not implemented"
handler is indistinguishable, to a conformance suite, from one that is
implemented and broken. Each later item adds its own.

**An unset variable expands to no root, not to `/`.** `os.ExpandEnv` turns
`$WORK/code` into `/code` when `WORK` is unset, and `/code` exists on some
machines. `expandRoot` returns the unexpanded path instead, so a typo in
`scan.roots` cannot silently become a scan of a real directory.

**A stale Unix socket is removed, but only after dialling it.** A crash leaves
the socket file behind and every subsequent start would fail with "address
already in use" for a service that is not running. Connecting first is what
distinguishes debris from a live service.

## Not done here

**htmx is not vendored yet.** `architecture.md` §3 calls for htmx and
`htmx-ext-sse` in `internal/web/static/`, but nothing renders HTML until the app
shell (T-0055), and adding third-party JavaScript to the repository is a
decision worth making when it is needed rather than in a scaffold. `mm.css` and
`mm.js` are placeholders naming the items that fill them.
