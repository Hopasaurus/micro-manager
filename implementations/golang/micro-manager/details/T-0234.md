# T-0234 — Columns M1e: op_tick.go v2 (ticklers), op_addmany.go v2, remaining --edit gaps, more v2 fixtures

The rest of T-0233's checklist, deferred out of its scope ('CLI --migrate wiring only' pacing choice). T-0233 shipped: --migrate now runs the legacy T-0044 repair and then the new versioned chain (mm.Store.MigrateVersion, T-0231) under one invocation, with --to VERSION, the git-uncommitted-changes warning (belongs in internal/cli, not the library — TestLibraryImports forbids os/exec in mm), and JSON/porcelain/human rendering for both phases. A real, serious bug in T-0231's migrate.go was also found and fixed along the way: a backlog.md or working-file line that failed to parse at all (e.g. unconvertible tags) was invisible to migrateOneToTwo's item-copy loop, so the item would have been silently dropped from the migrated board.md; it now refuses with an InvariantError naming what to fix first, proven by a new regression test. This unblocks T-0228 (M2). Remaining:

- op_tick.go generalized for tickler_stages (SOURCE->DEST) and tickler_dest, for both fire kinds — a v2 board's ticklers still never fire at all (Tick() hard-requires backlog.md)
- op_addmany.go's v2 bulk-add path (mirrors op_add.go's addV2, currently entirely v1: hardcodes Section and backlog.md)
- op_update.go's remaining v1-only rough edges (noted in T-0232's detail file too): setAnyField's "tickler" case checks `it.Section != SectionSomeday` instead of the directory's tickler_stages/it.Stage, so `--set tickler:X` is rejected on every v2 item regardless of its stage; neither setAnyField nor unsetAnyField has a "stage" case, so `--set stage:X` fails with a confusing "repeats field stage" parse error instead of a clear message (deliberately not a quick fix — routing a raw --set around --move's WIP/tickler-drop/started-stamping logic is a real behavior question)
- additional v2 test fixtures beyond board_test.go/migrate_test.go/v2ops_test.go, parallel to sample-data/sample1-3
- op_wip.go: SetWipLimit against a v2 directory currently just reports "no working.NN.md file to count from" (harmless, but not a clear v2-specific message); low priority, worth doing alongside the CLI's own --wip generalization (M4)
- `--init` still only creates version-1 directories; nothing in this session's scope touched it. Worth deciding whether M2/M3 need a way to --init directly at version 2, or whether --init-then-migrate is the intended path permanently

See notes/add-columns-plan.md#m1, T-0227/T-0231/T-0232's detail files for what already landed.
