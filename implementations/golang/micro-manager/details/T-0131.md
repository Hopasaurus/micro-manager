# T-0131 — Measure refresh traffic after Phase 1 ships; record the Phase 2 go/no-go

## Context

`research-app-fllicker.md` §6 — the gate between Phase 1 and Phase 2, and the
answer to `architecture.md` §4.5's open question 3 ("If board re-fetches turn
out to dominate, a per-column event may be worth it. Measure before splitting.").

Phase 1 (T-0128–T-0130) makes refreshes *invisible*; Phase 2 (T-0132–T-0134)
makes them *fewer and smaller*. Whether Phase 2 is worth building at all depends
on the traffic Phase 1 still produces. A legitimate outcome of this spike is
that Phase 1 alone is enough and the coarse events are fine — in which case the
Phase 2 items stay blocked and are cancelled.

## Requirements

- Instrument `board?fragment=1` (and status/check) for a real session:
  - bucket fetches by cause — `every 30s` backstop vs `sse:board` event;
  - count how many responses are byte-identical to the current DOM (i.e. the
    fetch changed nothing);
  - time the swap on a fixture with a large done column, before and after morph.
- Record the findings where the next reader will look: a `note` on this item,
  and a short "Measurement" section appended to `research-app-fllicker.md`.
- Record an explicit **go / no-go** for Phase 2, naming the numbers that
  decided it. On go, unblock T-0132; on no-go, cancel or re-defer
  T-0132–T-0134.
- If the backstop still dominates even though it is invisible (120 fetches/hour
  of idle traffic), note whether report option D2 (conditional polling — poll
  only when the SSE stream is down) is the cheaper next step instead of full
  per-column splitting.

## Notes

**2026-08-02** — NO-GO on Phase 2. Idle traffic is 100% backstop / 0% events (0 SSE events in 33 min); 20/20 refetches byte-identical; doneLimit already caps the board at ~6 KB gzip; broker poll is 27 us. C and B would remove none of the 240 fetches/hour that actually exist - D2 removes all of them. Full numbers in research-app-fllicker.md 8.

**2026-08-02** — Morph is FASTER than outerHTML at the default cap: 6.7 ms vs 11.9 ms median (32 cards). Only ~7% slower on a 312-card uncapped board. Phase 1 paid off.

**2026-08-02** — Found a live regression while measuring: morph leaks an htmx poll chain per externally-targeted board swap (every mutation). Filed as T-0138, high prio; it inflates the very number D2 targets.
