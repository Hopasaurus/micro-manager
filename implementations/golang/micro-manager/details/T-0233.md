## Notes

**2026-08-20** — Shipped ('CLI --migrate wiring only' slice): --migrate now runs the legacy T-0044 repair, then the new versioned chain (Store.MigrateVersion, T-0231) — one invocation, two independent phases, both reported. Added --to VERSION (targets a specific version instead of latest); a bad --to is a usage error before anything runs. The 'already at target version' case (ErrConflict) is treated as a benign no-op, not a command failure; a pre-existing violation blocking the chain (InvariantError) is reported as a warning ('version not migrated: ...', survives --quiet) rather than aborting, since the legacy repair's own progress already stands — matches the legacy repair's own 'fixes what it understands, leaves the rest reported' philosophy. Added the git-uncommitted-changes warning (spec-tools.md §5.3.4) in internal/cli, not the library, since TestLibraryImports forbids os/exec in mm. JSON gained a 'steps' field alongside the existing 'changes' field, kept byte-for-byte backward compatible for existing callers. Also found and fixed a real bug in T-0231's migrate.go while wiring this: a backlog.md/working-file line that fails to parse at all (e.g. unconvertible tags) is invisible to the parsed-items list migrateOneToTwo rebuilds board.md from, so the item would have been silently DROPPED from the migrated board — now refused with a clear InvariantError instead, proven by a new mm-package regression test. Updated 3 existing internal/cli tests whose assumptions predate the version-2 default (a bare --migrate on a healthy v1 project now also migrates it to v2, per spec-tools.md §5.3.4's documented default) by scoping them to --to 1, and added a new test proving the default-to-latest behavior explicitly, plus tests for --to's validation, the git-dirty warning, and the new JSON steps field. Full suite: mm + internal/cli 100% green; internal/web's pre-existing T-0226 failures untouched, still M4's job. Deferred to T-0234: op_tick.go (v2 boards still can't fire ticklers), op_addmany.go's v2 path, a couple of smaller --edit rough edges, more v2 fixtures, and whether --init needs a direct-to-v2 path.
