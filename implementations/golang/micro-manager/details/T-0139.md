# T-0139 — Conditional polling (D2): poll only while the SSE stream is down

Report option D2 of `research-app-fllicker.md` §3 D, promoted to an item by the
T-0131 measurement. Shipped.

## What changed

The freshness backstop was an unconditional `every 30s` clause on every
region's trigger — on an idle project with a healthy stream that was 100% of
the refresh traffic and 100% waste (T-0131: 65 fetches, zero SSE events, 20/20
byte-identical). The backstop now exists only while the stream is DOWN.

- **Templates.** The three data regions — `board`, `app-status` (both in
  layout.html and the `app-status-oob` copy in board.html), `check` — drop
  the `, every 30s` clause; their triggers are now `sse:board from:body`
  etc. The app root's `sse:theme` shell trigger was already backstop-free and
  stays that way.
- **mm.js.** New `SSE-down polling` block: `htmx:sseOpen` stops the interval,
  `htmx:sseClose` / `htmx:sseError` start a 5 s interval that issues each
  region's OWN `hx-get` through `htmx.ajax` with the morph swap and the
  region as source (so the morph extension resolves). Polling starts with an
  immediate round, so convergence does not wait half a window — the §2.3
  "polling alone" guarantee holds whenever the stream is down, which is the
  only time polling exists.
- **Region discovery.** The poll loop scans `[hx-trigger*="sse:"]` and keeps
  the elements that swap `morph` — the marker of a region that refreshes
  itself from a fragment. The app root's outerHTML theme shell is excluded: a
  full app re-render every 5 s is exactly the waste D2 exists to avoid. The
  regions self-describe, so no URL is duplicated into JavaScript.
- **sse_test.go.** `TestSSEStreamAttributesInShell` and
  `TestRefreshRegionsSwapWithMorph` now assert the trigger WITHOUT the
  polling clause (and that no `every` clause exists anywhere); the new
  `TestSSEDownPollingIsInTheClient` asserts the client wiring
  (sseClose/sseError start, sseOpen stops, 5000 ms, morph + own source).
  `TestBoardMutationsSwapOuterHTML`'s mm.js check was updated: the ONE morph
  swap is the poll, aimed at its own region — the T-0138 rule ("nothing may
  morph a region from outside it") still holds.
- **refreshcost_test.go.** `TestIdleFetchBudget` recorded the OLD arithmetic
  (120 fetches/hour per region forever). It now records the D2 model: 0
  fetches/hour per tab on a healthy stream; 3 regions × 720/hour only while
  the stream is down, until reconnect.

## Open questions, resolved

- **Does the check view keep a backstop regardless?** No. It gets the same
  conditional treatment as board and status: it is only in the DOM while the
  check view is open, and while the stream is down the 5 s interval covers it
  like the others. No special case.
- **Should the interval back off?** Not yet. The extension's own reconnect
  backoff (500 ms doubling to 64 s) bounds how long a full 5 s poll runs, and
  a down stream is precisely when the user wants fresh data. Backoff would
  be a second decision on top of this one.

## Tests

- The Go suite above, plus the behavioural JS suite of T-0111: three tests
  drive the real mm.js against jsdom — `sseError`/`sseClose` start the poll
  (immediate round + one 5 s tick), repeated closes do not stack intervals,
  `sseOpen` stops it for good, and the theme shell is not polled.
