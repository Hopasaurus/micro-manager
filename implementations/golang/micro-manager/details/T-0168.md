# T-0168 — Library: archive MUST move detail files into details-YYYY/, not strand them (spec-file-format.md §5.6)

## Why

T-0043 built `Store.Archive` before the spec said what archiving costs a detail
file, and chose the conservative option: strand the file in `details/`, whitelist
the I9 finding into the transaction baseline so the write is not blocked, and
report it in `ArchiveResult.DetailOrphans` and a warning. Its detail file says
in as many words that **T-0166 carries the spec question**.

T-0166 answered it, the other way: `spec-file-format.md` §5.6 now defines
`details-YYYY/` beside `done-YYYY.md`, and rule 3 makes moving the file and
rewriting the archived `detail:` field one operation. `spec-tools.md` §5.3.1
says an implementation that does one without the other is not conforming. So
the shipped behaviour is now a spec violation, and the library is the only thing
that has to change — the two validators do not, because I8 and I9 name
`details/` exactly and `details-2025/` is a different directory.

## What changes

`mm/op_archive.go`:

- Move each archived item's detail file from `details/<ID>.md` to
  `details-<YYYY>/<ID>.md`, where `YYYY` is the year of the month group being
  moved, and rewrite that item's `detail:` field on the archived line.
- Delete `acceptArchiveOrphans` and the I9 baseline whitelisting it does. With
  the file moved there is no orphan to accept, and the transaction's "refuse
  what I introduced" rule then covers archiving with no exception carved out of
  it — which is the point.
- `ArchiveResult.DetailOrphans` becomes `DetailsMoved` (or similar); the warning
  changes from "stranded N files" to "moved N detail files into details-YYYY/".
  The ID-pool warning stays exactly as it is (§5.3, §10.5).
- Write ordering (§7 rule 4) covers both halves: `done-YYYY.md` and
  `details-YYYY/` are written **before** `done.md` and `details/` give anything
  up, so an interruption leaves a duplicate to re-run over rather than a hole.
  `TestArchiveHealsAnInterruptedRun` is the existing case; it needs the detail
  half added.

Tests to rewrite rather than extend: `TestArchiveReportsTheDetailFilesItStrands`
asserts the old contract outright, and the tail of
`TestArchiveOnTheRepositorysOwnBoard` counts findings against reported orphans —
on this board that is 51 detail files, which under §5.6 becomes 51 moves and
zero findings.

Also worth adding, since §5.6 rule 4 promises it: a test that a hand-restore of
one archived line into `done.md` **without** moving its detail file back is
reported by the validator (I8), so the spec's "fails loudly" claim is checked
rather than asserted.

## Not in scope

`--age DAYS` and the CLI switch: `spec-tools.md` §5.3.1 defines both, and no
optional operation is wired into the CLI yet — that is **T-0167**.
