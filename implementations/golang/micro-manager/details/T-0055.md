# T-0055 — Render the app shell, nav, project switcher and status bar

## As built

`internal/web/view.go`, `templates/layout.html`, `templates/error.html`,
`static/mm.css`, and htmx vendored at 2.0.7 with `htmx-ext-sse` 2.2.4.

**Every `data-*` attribute is computed in Go**, never derived in the browser.
State the client invents is state the server cannot be held to, and the external
suite reads these attributes as the truth about what the service did.

**The theme is inlined in the document**, not fetched. That is what makes §8.7's
"no flash of the previous theme when switching projects" true by construction
rather than by timing: the new values arrive in the document that carries the
new view.

**Theme values are escaped as a gate, not as decoration.** A theme file is
editable and importable, `template.CSS` bypasses escaping, and a `gui` token
takes any string — so a value containing `<`, `>`, `{`, `}` or `;` is dropped
rather than sanitised into something half-meant. A test feeds a token
`x</style><script>alert(1)</script>` and asserts it never reaches the document.

**Nav links exist on every route**, pointing at `/projects` when no project is
open. §5.1 forbids dropping a required testid conditionally, so `nav-board` is
present whether or not there is a board to go to.

**The status bar validates on every render.** §5.2 requires `status-check` to
carry `data-violations` on every route so a suite can assert cleanliness without
opening the check view. A directory small enough to be a todo list is cheap
enough to validate per request.

**The not-found view ships here**, because `errors.go` deferred its full-page
form to "when the app shell exists" and §4.1 rule 4 requires it: an unknown
`projectId` is a 404 with a view, never a redirect to `/`.

## The bug the browser found that the tests did not

Every item menu rendered **open**. The markup carries `hidden`, and the tests
asserted the attribute is present — but `.mm-item__actions { display: flex }`
silently beats the user agent's `[hidden] { display: none }`. A global
`[hidden] { display: none !important }` fixes it.

Worth remembering: an attribute assertion is not a visibility assertion, and the
external browser suite of §12 is what would eventually have caught this.
