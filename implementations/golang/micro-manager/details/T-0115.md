# T-0115 — CLI: --init --prefix/--id-width and per-directory ID parsing

Third task of the T-0112 spike. Depends on T-0113 (grammar) and T-0114
(library honors it).

## Today

- `cli.ParseID` (internal/cli/parse.go) wraps `mm.ParseID`, which hardcodes
  `T-`/4 digits.
- `--init` writes `next_id: T-0001` unconditionally (mm/init.go:173).

## What to change

- `--init` gains `--prefix P` and `--id-width N` (mirroring the existing
  `--slot-width`), writing the frontmatter fields.
- Every ID-taking operation (`--add/--show/--edit/--move/--remove/--start/
  --pause/--finish/--block/--unblock/--note`) parses per the directory's
  declared grammar — the loosen-and-validate pattern: the CLI accepts
  `prefix + digits`, the library validates against the directory.
- `--status/--next/--search` output renders the directory's own IDs (they
  mostly do already, since they print parsed values — verify).
- Usage/help text documents the new switches; the usage/parser drift test
  covers them automatically.

## Verify

`--init --prefix X --id-width 3 --project P` then `--add` produces `X-001`;
the same commands on an unconfigured directory produce `T-0001`. The
`--dry-run` of an add shows the directory's own ID shape.
