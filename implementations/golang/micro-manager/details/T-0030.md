# T-0030 — Build the CLI switch parser, one operation per invocation

## Context

`spec-tools.md` §3.2 requires the operation to be selected by a **switch**, not
a positional subcommand: `mm --add "…"`, never `mm add "…"`. Exactly one
operation switch per invocation; zero is a usage error, two or more is a usage
error naming both.

## Requirements

- Long form for every switch; short aliases optional but must appear in `--help`.
- Accept both `--switch VALUE` and `--switch=VALUE`.
- `--` ends switch parsing.
- Unknown switch is a usage error, never silently ignored.
- Repeated modifiers: last wins, except documented accumulating ones (`--tag`).
- ID arguments accept `T-0042`, and should also accept `42` or `0042` and
  resolve them — the prefix is friction the format imposes for machine reasons.
- Conflicting arguments (`--all` with an explicit directory) are usage errors.

## Open question, needs deciding early

Go's `flag` package does not do this well: it has no repeated-flag support, no
`--switch=value` plus `--switch value` symmetry for all types, and no way to
express "exactly one of this set". Choose one:

1. Hand-rolled parser — full control, matches the spec exactly, maybe 200 lines
   and needs its own tests.
2. A third-party parser — adds a dependency, which `../../AGENTS.md` says needs a
   stated reason, and most are built around subcommands, which is the shape this
   spec explicitly rejects.

Leaning hand-rolled: the surface is flat by design, which is the case a
hand-rolled parser handles well.
