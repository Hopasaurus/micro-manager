# T-0118 — Per-task ID prefixes: per-prefix counters and I2 per counter (gated on the spec decision)

Sixth task of the T-0112 spike — the "or even on a per task basis" reading of
the request. **Gated on T-0113**: T-0113 must decide whether mixed prefixes
within one directory are part of the grammar at all. Recommended default: not
in v1 (see below); this task is the phase that picks it up if the decision
goes the other way.

## Why it is disruptive

- `next_id` is ONE counter per directory today (I2: every ID is below
  `next_id`, never reused). Mixed prefixes need either per-prefix counters
  (a map in the frontmatter, or one field per prefix) or a shared counter with
  prefixes stamped on — and I2's wording ("every ID is below next_id") only
  makes sense within one prefix's numbering.
- Every parser, the item-line renderer, `details/<ID>.md` lookup, search, the
  CLI's ID parsing, check.sh, and the GUI's per-item routes must resolve which
  prefix a typed ID belongs to.
- A prefix becomes part of an item's identity, so changing it is a rename —
  I9's title/detail coupling is per-ID, but the detail path depends on the ID.

## If accepted

Define the counter model in the spec first (T-0113's decision), then: library
allocation per prefix, I2 per counter, check.sh per-prefix validation,
CLI/GUI display. Budget for it being the largest of the six.

## Verify

A directory where one item is `X-001` and another `Y-001` round trips through
every operation without violating the per-prefix I2.

## Update (post-ship): decided NOT in v1

T-0113's decision went the recommended way: **one grammar per directory**, and
per-task prefixes are explicitly out of v1 (spec-file-format.md §3.3.2 rule 1:
"A directory containing IDs in more than one grammar is invalid"). The gate
this task was waiting on resolved against the feature, so the per-prefix
counter model, I2 per counter, per-prefix check.sh validation, and the
CLI/GUI display work were all never built — correctly, because the spec does
not describe them.

What this task shipped instead is the **guard that makes the spike's scenario
illegal everywhere**, so the decision is enforced, not just written:

- **`testdata/broken-mixed-prefix`** — the verify scenario as a broken
  fixture: an `X`/3 directory whose Someday holds `Y-001`, a perfectly
  well-formed ID in its own grammar. Both validators report exactly
  `backlog.md:23 malformed item line` — the foreign prefix is its only
  finding. (The existing `broken-id-grammar` fixture also had a wrong-width
  case; this one isolates the mixed prefix.)
- **The oracle test** (`TestValidatorAgreesWithCheckShOnFixtures`) runs the
  new fixture through check.sh and the Go validator and asserts the finding
  sets match, via the `brokenInvariants` map.
- **`TestMixedPrefixesAreOneGrammarViolation`** (`mm/grammar_test.go`) opens
  the fixture and asserts the single finding names `Y-001`.
- **`TestMixedPrefixesCannotBeWritten`** asserts the library cannot *produce*
  the scenario either: `Y-001` does not parse in the `MM`/3 grammar, `Get`
  does not resolve it, and allocation stays inside the declared prefix, so no
  per-prefix counter state is needed.

I2 stays exactly as the format always said: one monotonic `next_id` per
directory, in the declared grammar (§3.3.2 rule 5). `plan-id-widths.md`'s two
T-0118 references now record the NOT-in-v1 closure instead of assuming the
feature lands.
