# T-0002 — Define the core domain types: Item, Slot, Directory, Change, Violation

## Context

`spec-tools.md` §6.1 lists the types by name and field. Field names are
normative; Go representation is ours to choose, and two of those choices are
load-bearing.

## Requirements

- `Item.Extra map[string]string` holds unregistered fields. Format spec §9 makes
  them the extension point, so every operation that rewrites an item carries
  them through untouched. This is the field most likely to be quietly dropped.
- **Do not use `time.Time` for `Created`, `Started`, `Done`.** The format is
  date-granular with no timezone (format spec §3.3). A `time.Time` invites a
  timezone bug that shifts a `done:` date across a month boundary and files the
  item under the wrong `## YYYY-MM` heading. Use a `Date` type wrapping
  year/month/day with `Parse`/`String` and an explicit zero value.
- `Prio`, `State`, `Section`, `Outcome` are typed strings with `Parse` and
  `String`, so an invalid value cannot be constructed silently.
- Zero values must be meaningful: an absent `prio` means `med` on read but must
  serialise back as absent, not as `prio:med`, or round-trip fidelity breaks.
- `Location` carries file and line for diagnostics on every parsed item.

## Open questions

- Is `Position` stored on the item or derived from its index at read time?
  Derived is harder to get stale; stored is easier for callers. Leaning derived,
  recomputed on every list.
