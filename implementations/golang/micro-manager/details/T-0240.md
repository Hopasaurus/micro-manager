# T-0240 — Generalize column collapsing to every stage (spec-gui.md §5.5/§9.3)

Follow-up from T-0239's research spike
(`project/research-column-collapse.md`). `spec-gui.md` already documents
column collapsing as generic to any stage, not only Someday; the Go
implementation still hard-codes the whole mechanism to the literal stage
`"someday"`. `TestAuditTestids` does not currently require otherwise (spec
explicitly leaves "every column or only some" to the implementation), so
this is a scoping/feature task, not a spec-compliance bug.

Read `project/research-column-collapse.md` in full before starting — it
already traces exactly what is and is not generic today (§1-2), resolves
the one open design question (§3: encode the collapsed set as a
comma-separated stage list, `X-Collapsed-Stages` header +
`mm:collapsed-stages:<project>` localStorage key, matching this
codebase's existing `tags:`-style comma-list convention), confirms the
config default (§4: `ui.board.collapsedStages`) and the live per-request
header are complementary, not competing, and recommends offering the
toggle on every column, not a subset (§5).

## Shape of the work (§6 of the report)

1. `mm/config.go`: `BoardConfig.ShowSomeday bool` → `CollapsedStages
   []string`, reader becomes a comma-list parse under
   `ui.board.collapsedStages`, default `["someday"]`. No shipped config
   in this repository sets `ui.board.showSomeday` today, so there is
   nothing real to migrate.
2. `internal/web/board.go`: `somedayCollapsed(c)` generalizes to read the
   full `X-Collapsed-Stages` list; both `buildBoard` and `buildBoardV2`'s
   per-column loops set `col.Collapsed` from it unconditionally instead
   of gating on `key == "someday"`.
3. `internal/web/templates/partials/board.html`: drop the someday-only
   gates on the toggle button and `data-collapsed`; toggle testid becomes
   `board-column-{{$c.Key}}-toggle` for every column.
4. `internal/web/static/mm.js`: generalize the localStorage key, the
   click handler (matching `[data-testid$="-toggle"]` generically rather
   than the one hard-coded testid), and `restoreSomedayState` to loop
   every column. Seed the initial per-project default from the config's
   list via a data attribute on the board root (no localStorage entry
   yet case).
5. Tests: `board_test.go`'s collapse assertions extend to a second
   column and its "ready never carries data-collapsed" check inverts;
   `audit_test.go`'s `board-column-<slug>-toggle` instance table grows to
   require every rendered stage's toggle. `dragdrop_test.go`'s
   `TestCollapsedColumnsResolveADrop` needs no change — already generic.

Nothing here touches the `mm` library beyond the config struct: no new
routes, no new spec text, no v1/v2 split (the mechanism is identical in
shape for both, since `columnData.Collapsed` is already version-agnostic).

## Notes

**2026-08-21** — Shipped exactly the shape §6 above described, plus one
addition beyond the report's minimum: every v1 column (someday, ready,
blocked, working, done) and every v2 stage column now gets the toggle,
including `working` and `done` (the report's §5 already recommended this
— nothing structurally set them apart from any other column).

- `mm/config.go`: `BoardConfig.CollapsedStages []string`, parsed via the
  existing `strs` helper under `ui.board.collapsedStages`; default
  `["someday"]`. New `mm/config_test.go` coverage:
  `TestBoardCollapsedStagesIsAStringList`, plus a default-value assertion
  added to `TestDefaultsMatchTheSpec`.
- `internal/web/board.go`: `somedayCollapsed` replaced by
  `collapsedStages(c) map[string]bool`, parsing
  `X-Collapsed-Stages` as a comma list. Both builders set
  `col.Collapsed` from it for every column (`buildBoard`'s three backlog
  sections, its `working`, and the shared `doneColumn`; `buildBoardV2`'s
  per-stage loop and its own `doneColumn` call). `boardData` gained
  `DefaultCollapsedStages string` (the config list, comma-joined) so the
  client can seed a fresh project with no stored preference yet.
- `internal/web/templates/partials/board.html`: the toggle button and
  `data-collapsed` no longer gate on `eq $c.Key "someday"` — every column
  renders both, testid `board-column-<key>-toggle`. The board root
  carries the new `data-default-collapsed-stages` attribute.
- `internal/web/static/mm.js`: `mm:someday-collapsed:<project>` (one
  boolean) became `mm:collapsed-stages:<project>` (a comma list); the
  click handler and the restore-on-load function derive a column's key
  from its own testid (`board-column-<key>[-toggle]`) rather than a
  literal string, so they work unmodified for any stage a project
  declares, built-in or custom. The restore path distinguishes "no
  localStorage entry yet" (`=== null`, seeds from
  `data-default-collapsed-stages`) from "explicitly recorded, nothing
  collapsed" (empty string) — the same null-vs-empty distinction
  T-0097's fingerprint fix turned on.
- Tests: `board_test.go`'s `TestSomedayCollapseRenderedFromHeader` became
  `TestColumnCollapseRenderedFromHeader`, covering two columns
  collapsing independently over the new header shape, and
  `TestBoardColumnsAndOrder` now expects a `-toggle` testid on every
  column. `audit_test.go`'s `board-column-<slug>-toggle` instance table
  now requires every rendered column's toggle instead of pinning one.
  Four new `internal/web/jstest/mm.test.js` cases cover the click
  handler, the multi-column comma-list storage, the request header, and
  the config-default seeding path — none of this client logic had test
  coverage before (the old someday-only version didn't either).
  `dragdrop_test.go`'s `TestCollapsedColumnsResolveADrop` needed no
  change, confirming the report's finding that the drag/drop layer was
  already fully generic.

Verified live in a browser (isolated config-home, a scratch copy of
`clean-v2-full`): a fresh project opened with Someday already collapsed
(the config default) with every other column expanded; clicking Ready's
toggle collapsed it independently, and Review — a custom v2 stage with no
special-case status anywhere in the code — collapsed the same way,
confirming the mechanism truly generalizes past the four built-in names.
A full page reload preserved exactly the collapsed set
(`localStorage` read back `"someday,ready"`), and expanding Ready again
correctly dropped it from the stored set while leaving Someday's default
untouched. No config file was written by any of this — the preference
stayed entirely client-side, as designed.

`go test ./...`, `go vet ./...`, and `gofmt -l .` are all clean; the
`internal/web/jstest` node suite (36 tests) passes in full.
