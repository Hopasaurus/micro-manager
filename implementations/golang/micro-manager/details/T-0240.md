# T-0240 — Generalize column collapsing to every stage (spec-gui.md §5.5/§9.3)

Follow-up from T-0239's research spike
(`project/research-column-collapse.md`). `spec-gui.md` already documents
column collapsing as generic to any stage, not only Someday; the Go
implementation still hard-codes the whole mechanism to the literal stage
`"someday"`. `TestAuditTestids` does not currently require otherwise (spec
explicitly leaves "every column or only some" to the implementation), so
this is a scoping/feature task, not a spec-compliance bug.

Read `project/research-column-collapse.md` in full before starting — it
already traces exactly what is and is not generic today (§1-2), resolves
the one open design question (§3: encode the collapsed set as a
comma-separated stage list, `X-Collapsed-Stages` header +
`mm:collapsed-stages:<project>` localStorage key, matching this
codebase's existing `tags:`-style comma-list convention), confirms the
config default (§4: `ui.board.collapsedStages`) and the live per-request
header are complementary, not competing, and recommends offering the
toggle on every column, not a subset (§5).

## Shape of the work (§6 of the report)

1. `mm/config.go`: `BoardConfig.ShowSomeday bool` → `CollapsedStages
   []string`, reader becomes a comma-list parse under
   `ui.board.collapsedStages`, default `["someday"]`. No shipped config
   in this repository sets `ui.board.showSomeday` today, so there is
   nothing real to migrate.
2. `internal/web/board.go`: `somedayCollapsed(c)` generalizes to read the
   full `X-Collapsed-Stages` list; both `buildBoard` and `buildBoardV2`'s
   per-column loops set `col.Collapsed` from it unconditionally instead
   of gating on `key == "someday"`.
3. `internal/web/templates/partials/board.html`: drop the someday-only
   gates on the toggle button and `data-collapsed`; toggle testid becomes
   `board-column-{{$c.Key}}-toggle` for every column.
4. `internal/web/static/mm.js`: generalize the localStorage key, the
   click handler (matching `[data-testid$="-toggle"]` generically rather
   than the one hard-coded testid), and `restoreSomedayState` to loop
   every column. Seed the initial per-project default from the config's
   list via a data attribute on the board root (no localStorage entry
   yet case).
5. Tests: `board_test.go`'s collapse assertions extend to a second
   column and its "ready never carries data-collapsed" check inverts;
   `audit_test.go`'s `board-column-<slug>-toggle` instance table grows to
   require every rendered stage's toggle. `dragdrop_test.go`'s
   `TestCollapsedColumnsResolveADrop` needs no change — already generic.

Nothing here touches the `mm` library beyond the config struct: no new
routes, no new spec text, no v1/v2 split (the mechanism is identical in
shape for both, since `columnData.Collapsed` is already version-agnostic).
