# T-0149 — Drops over the drop placeholder silently never fire

The fix task created by [[T-0141]]. T-0141 reproduces the failure in a real
browser and validates the approach below; read it first for the event log and
the browser verification.

## Symptom

Dragging a card up and releasing with the pointer over the drop placeholder (a
column top, or the gap between two cards) fires **no `drop` event**: the item
does not move, no request is issued, no error is shown. Downward drags mostly
work because the placeholder sits below the pointer there.

## Root cause

The placeholder (`.mm-drop-placeholder`, 32 px, `mm-space-6`) is a normal flex
child of the column body. `hoverTarget` removes and re-inserts it on every
dragover (T-0110), and inserting it shifts every card at or below the insertion
point down by 32 px. The browser hit-tests the last dragover to the card under
the pointer; the handler then shifts that card away; on release the cached drop
target is no longer under the pointer and the drop is delivered nowhere.

## Fix (validated, do not re-derive)

1. `internal/web/static/mm.css`:
   - `.mm-column__body` — add `position: relative` (anchor for the absolute
     placeholder).
   - `.mm-drop-placeholder` — add `position: absolute; left: 0; right: 0;
     pointer-events: none`. Out of flow, the placeholder never shifts a card.
     `pointer-events: none` keeps it from ever being the drag/drop target (it
     is removed and re-inserted each dragover, so as a target it would be
     detached at release); events land on the card/body behind it, which is
     stable. Keep the existing height/border/border-radius.
2. `internal/web/static/mm.js` `hoverTarget` — replace the
   `insertBefore/appendChild` placement with: `body.appendChild(placeholder)`,
   read `placeholder.offsetHeight`, then set `placeholder.style.top` (px,
   relative to the body) so the placeholder's centre sits at the insertion
   point: body top for index 0; `(above.bottom + below.top) / 2` between
   cards; `last.bottom + 8` for append. (Compute the rects against the body's
   `getBoundingClientRect().top`.)
3. `internal/web/static/mm.js` `drop` handler — before `commitMove()`, clear
   any placeholder, then re-derive the index from the drop event's own
   `clientY` with the same midpoint walk the dragover handler uses (extract it
   into a shared helper). This makes the release position authoritative and
   guards the latent frame-coalescing race T-0141 describes.

The dragover handler's clear-before-measure (T-0110) can stay as-is; it is
harmless once the placeholder is out of flow.

## Update (post-ship)

Shipped. `mm.css` anchors the body (`position: relative`) and makes the
placeholder `position: absolute; left: 0; right: 0; pointer-events: none`;
`mm.js` `hoverTarget` appends the placeholder and sets `style.top` to the
insertion point, and the `drop` handler re-derives the index from the drop
event's own `clientY`. The dragover handler no longer clears-then-measures:
with the placeholder out of flow the cards never shift, so the T-0110 ordering
is moot and the handler is one `hoverTarget(body, indexAt(...))` call.

Verified in a real browser (headless Chromium): 11/11 intra-column drops across
the upper/lower halves of every card, both boundaries, top and bottom, and both
directions land at exactly the pointer's index; cross-column append,
working→blocked (prompt dialog), and the keyboard move mode all still work.
The superseded guard is now `TestPlaceholderIsOutOfTheColumnFlow`, which asserts
the out-of-flow position in both `mm.css` and `mm.js`. mm.js is 694 lines,
under the 700-line guard.
