# T-0060 — Render the report view with period controls and copy as markdown

## As built

`internal/web/report.go`, `templates/report.html`, plus `Report.Markdown()` in
the library.

**The markdown moved into the library.** §5.7 requires `report-copy` to place
*the same paste-ready markdown the CLI produces* on the clipboard. Two renderers
cannot be held to that; one can. `mm.Report.Markdown()` is a pure function — the
library still writes to no stream, it returns a string — and `internal/cli`
now calls it, so the CLI's output is byte-identical to before and identical to
the GUI's by construction. A test renders both and compares.

**The copy text is carried in the DOM**, in `data-clipboard` and a hidden `pre`.
A test can then read exactly what would be pasted without a clipboard
permission, and `mm.js` copies that value rather than rendering a second time.

**An ungrouped report still emits a group.** The DOM shape must not depend on a
setting, or a suite asserting `report-group-*` finds nothing when grouping is
off.

**A group key is sanitised before it reaches a testid.** Grouping by tag makes
the key user data, and `report-group-<key>` is a locator.

## The precedence bug this found

`data-period-source` must distinguish `switch`, `config` and `default` (§5.7).
Reading the *merged* configuration cannot do that: `DefaultConfig()` sets
`report.period: "last-week"`, so every unconfigured report claimed its period
came from `config`.

The server now keeps the system config **file** alongside the merged view and
asks what the user actually wrote — project config first, then system, per
§9.4's per-leaf merge. Empty means nobody wrote one and the built-in applies.
The merged `Config` remains what everything else reads; provenance questions
need the file.

**The environment step is skipped entirely.** For the CLI, `MM_REPORT_PERIOD`
occupies slot 4 of §5.1.11. A UI service must not read it (§9.2) — the service
outlives any one user's shell — so config takes that slot and a test sets the
variable and asserts it changes nothing.

## Two defects found on the way

**`Server.addr` was a data race.** Written by Echo's `ListenerAddrFunc`, read by
whoever wants the address, unsynchronised. It surfaced as an intermittent test
failure and is now behind a mutex. `go test -race` is clean.

**Port 0 could not mean "let the OS choose".** `New` defaulted it to 7717, so a
test asking for an ephemeral port silently got the real one and failed when a
service was already running there. The default now lives only in
`DefaultConfig`, where §9.2 puts it; `cmd/mm-ui` always passes a real port, and
§9.6 rule 7's "never silently pick another port" is unaffected — that is about a
port already in use, which still fails loudly.
