# T-0114 — Library: honor the directory's declared ID grammar (id_prefix/id_width)

Second task of the T-0112 spike. Depends on T-0113 (the spec defines the
grammar first; spec-file-format.md wins).

## The grammar the library must honor (§3.3.2)

- `id_prefix`: **one to four ASCII letters, ALL UPPERCASE** (`T`, `MM`, `FOO`).
  Lowercase and mixed case are invalid; matching is exact.
- `id_width`: one or more ASCII digits, default `4`; zero-padded. Width 3–6 is
  RECOMMENDED — warn, never fail, outside that range.
- Both keys are optional in backlog.md frontmatter; each defaults independently
  (`T` / `4`). Absent keys = today's behavior, byte-identical.
- `next_id` stays ONE monotonic counter in the declared grammar; counter space
  is `10^W − 1`.

## Today

- `mm.ParseID` (mm/item.go:20) hardcodes a single letter before `-`:
  `strings.HasPrefix(s, "T-") || strings.HasPrefix(s, "t-")` then slices
  `s[2:]` — wrong for a multi-letter prefix (`MM-001`) and for exact-case
  matching (it accepts `t-` today; the spec now forbids it). The digit cap
  `len(digits) > 4` is also hardcoded.
- `next_id` is allocated/rendered as `T-%04d` (mm/init.go:173).
- `details/<ID>.md` paths, item-line rendering, and the validator all assume
  the same shape.

## What to change

- Read `id_prefix`/`id_width` from backlog.md frontmatter (defaults `T`/4) and
  carry them on the Store/directory model, exactly as `SlotWidth` is handled
  today (mm/init.go:22-25 shows the existing per-directory-width pattern).
- `ParseID` must parse the ID by token against the declared grammar — not by a
  fixed slice — and reject: a prefix that is not 1–4 uppercase ASCII letters,
  a width mismatch (exactly `id_width` digits), and any case deviation.
- Allocation zero-pads to `id_width`; `next_id` increments in the declared
  space; warn (never fail) when `id_width` is outside 3–6.
- The validator checks every item ID and `next_id` against the declared
  grammar, in lockstep with check.sh (T-0116).
- Watch the §3.1 hazard: anything that slices the item-line prefix by byte
  offset must use the directory's declared grammar — the prefix is now
  VARIABLE (1–4 letters) and the width variable too, so offsets are only safe
  under the default grammar (per §4.2 rule 2).

## Verify

A directory with `id_prefix: MM` / `id_width: 3` add/start/finish/search round
trips with `MM-001`-style IDs; `mm-001` and `M-001` are rejected; a directory
without the fields behaves exactly as before. The Go validator agrees with
check.sh on both.
