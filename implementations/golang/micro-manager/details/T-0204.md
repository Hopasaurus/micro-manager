# T-0204 — Tickler not moving old items?

There are two item: T-0193 & T-0198 that look like they should have been moved.

Investigate and report why they have not moved.  Create tasks to fix if needed.

Create a task add logging when the schedule checker processes that shows what items are scheduled and when they will move. 

## Findings (2026-08-07)

**They never moved because the tickler has never run — not a scheduling bug.**

T-0193 (`tickler:2026-08-06@06:44`) and T-0198 (`tickler:2026-08-06@09:32`)
are one-shot schedules that came due on 2026-08-06. No `tickled:` stamp
existed on any item anywhere in the directory, so no run had ever evaluated
them.

The tickler has exactly two drivers, both opt-in by design
(spec-gui.md §2.4; `TicklerConfig.Interval`, system-scoped, empty = off):

1. **The UI service goroutine** — only when the system config
   (`~/.config/micro-manager/config.json`) sets `tickler.interval`. It does
   not: the file has no `tickler` key, so `ticklerInterval()` returns 0 and
   the loop never starts. The currently running `mm-ui` (pid 17547) is
   therefore not ticking, and the "tickler service on" log line is absent.
   Additionally, even when enabled, the UI path ticks only **held** boards
   (`registry.heldStores()`) — a directory whose board was never opened in
   the browser is never ticked by the service.
2. **`mm --tick` from a cron** — nothing in the repository or on this host
   schedules it (SKILL.md notes a cron is expected but none exists).

**Verified working:** `mm --tick --dry-run` reported exactly the two due
items; the real run moved both to `## Ready`, dropped `tickler:`, stamped
`tickled:2026-08-07`. T-0199 (`mon@07:00`, recurring) is correctly not due
until Mon 2026-08-10; T-0200 (`2026-08-20`) not due yet.

**Gaps this exposed (new tasks created 2026-08-07):**

- T-0205 — no logging shows what is scheduled and when it will fire, so
  "why didn't it move" is unanswerable from the logs. Requested by this
  ticket: log the scheduled set (Ticklers) on every pass.
- T-0206 — a disabled tickler is silent: mm-ui starts without saying that
  the service that is supposed to move items is off. Warn at startup when
  `tickler.interval` is unset.
- T-0207 — the two drivers and the held-boards coupling are undocumented;
  document them, and enable the service locally (system config + restart)
  so the tickler actually runs.
