# T-0272 — Implement markdown viewer for item detail

When an item is loaded it should be shown as rendered html.  There should be a way to edit the item, possibly by clicking a button to switch to edit mode. Then there should be a way to switch back to rendered view before saving to see if it looks ok.

## Markdown implementation decision

Use a locally vendored, version-pinned `markdown-it` browser build, following the recommendation from T-0271.

- Store the browser artifact and its license under `internal/web/static/` so it is embedded into the Go binary and works without a CDN or runtime network access.
- Load it before `mm.js` and use one shared parser configuration.
- Keep source HTML disabled (`html:false`). Also leave `linkify` and `typographer` disabled initially. Raw HTML from a detail file must render as inert text, never executable markup.
- Do not add plugins until a specific syntax requirement is accepted. If GFM tables or task lists are required, enable only the minimum well-maintained extension necessary.
- Record the exact upstream version, source URL, checksum, license, and update procedure for the vendored artifact.

## Interaction

- Opening an item shows the detail as rendered HTML by default.
- An explicit Edit control switches from the rendered view to the existing Markdown textarea.
- A Preview control renders the current unsaved textarea contents without saving them.
- The user can switch between Edit and Preview without losing unsaved text, selection, or scroll position.
- Saving uses the raw Markdown source, never the generated HTML.
- An empty detail should have a clear empty state and remain editable.

## Integration shape

- Put HTML-escaped Markdown source in an inert element such as a hidden textarea or template and read it with `.value` or `.textContent`. Never interpolate file contents into a JavaScript literal.
- Add a small renderer in `mm.js` and run it on initial load and after htmx replaces the item panel.
- Scope presentation styles under `.mm-markdown`, covering headings, paragraphs, lists, blockquotes, links, inline code, fenced code, tables, horizontal rules, and task-list checkboxes.
- Keep the current item revision and concurrent-edit protections intact. Preview is entirely local and must not mutate the item or advance its revision.

## Acceptance coverage

- Common Markdown constructs render correctly in the initial view and unsaved preview.
- Editing and previewing repeatedly preserves the raw source.
- Save persists exactly the textarea Markdown and returns to rendered view.
- HTML/event-handler payloads and unsafe URL protocols cannot execute.
- Rendering is reapplied after htmx swaps and remains compatible with the current CSP (`script-src 'self'`).
- Keyboard navigation, focus restoration, empty details, malformed Markdown, and a bounded large input are covered.
