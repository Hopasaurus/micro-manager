# T-0044 — Implement migrate for older directory layouts

## Scope

`spec-tools.md` §5.3 names exactly three legacy shapes, and `mm/op_migrate.go`
repairs exactly those:

| Shape | Repair | Spec |
|---|---|---|
| `working.md` | renamed to the lowest free `working.NN.md` | §5.2.1 rule 4 |
| no `project` in `backlog.md` | `--project NAME`, or the parent directory's name | §5.1, I7 |
| `tags: [infra, ci]` | `tags:infra,ci`, on item lines and in slot frontmatter | §5.2.2, §10.3 |

Nothing else. A field reordered or a heading reworded is not a format revision,
and a migration that rewrites what it was not asked to rewrite is
indistinguishable from corruption in the diff.

## Decisions

**It tolerates violations it does not own, where `--fix` refuses.** `--fix`
blocks on anything outside I1/I2 — including I10, which a `working.md` breaks.
If `--migrate` blocked the same way, a legacy directory that also had a
duplicate ID could be repaired by neither tool. `--migrate` is the first thing
you run on an old directory; it fixes what it understands and hands you one
`--check` can tell the truth about.

**Two refusals, both "would write a directory `--check` rejects":** a
`working.md` whose CONTENT is not a working file (the violations come back under
the name it would have had), and a conversion that would REVEAL a duplicate ID —
a line that could not be parsed was never counted against I1, so making it
readable can introduce the finding. The transaction refuses and names the
duplicate, which is what a person needs; `--fix` cannot help with a duplicate it
cannot see.

**The tag rewrite is textual, not model-level.** A malformed `tags:` value is a
PARSE failure, so the item never reaches the model — there is nothing to
re-render. The migration rewrites the line, which is what the repository's
"line splices over the retained original" rule asks for anyway.

**`--project` is the switch `--init` already uses.** It means the same thing in
both. Absent, the name comes from the PARENT directory: the board's own name is
always one of the six recognized ones and carries no information. The chosen
name is reported either way — a guess is a starting point, but a silent one
would be a decision.

## Two traps

**Order: tags before project.** The tag rewrite addresses lines by the number
they had when the file was parsed, and writing a missing `project` INSERTS a
line into the frontmatter, moving every line below it. The other order silently
rewrote the line after each item — turning the item into a duplicate of its
neighbour, which the pre-commit check then reported as an I1 the migration had
"introduced". The symptom named a duplicate ID; the cause was an off-by-one.

**`violationKey` had to stop reading line numbers inside messages.** It already
ignored a finding's own line ("a splice moves unrelated findings up or down
without making them new"), but I1's message embeds the OTHER copy's location —
`T-0001 is already defined at backlog.md:11`. Insert a `project:` line and that
message becomes `:12`, so a pre-existing duplicate looked introduced and the
migration refused for a violation it had not touched. `maskLineRefs` now blanks
the line number in every `<file>.md:<n>` reference.

That change exposed something else worth knowing: **`TestConflictMarkersBlock
Mutations` was passing for the wrong reason.** The block came from the same
accidental shift — the two sides of the conflict carried duplicate IDs, and the
I1 message moved. Markers themselves were pre-existing findings and blocked
nothing. `tx.begin` now refuses a transaction outright when the model holds
conflict-marker findings, which is what the test always claimed and what
`spec-file-format.md` §5.1 means by "the one reserved exception": a half-merged
file is not a directory with a problem in it, it is two directories that have
not been reconciled, and writing over one discards a side. Reads stay open.
`TestAConflictMarkerAloneBlocksMutations` pins it with a fixture whose only
finding is the marker, so it cannot pass by accident again.

## Verification

- `mm/op_migrate_test.go`: the whole point (a directory the checker rejects goes
  in, one it accepts comes out), dry run and idempotence, the project name in
  its three cases, the rename beside existing slots and at a declared width, the
  two refusals, the ten converter shapes including quoted scalars and `[]`, an
  unconvertible value left alone with the rest of the migration still running,
  and tolerance of a merge duplicate followed by a `--fix` that can now run.
- `internal/cli/migrate_test.go`: the switch end to end, `--project`, the three
  output modes, the warning surviving `--quiet`, and a current directory saying
  so rather than staying silent.
- Run for real against a hand-written legacy fixture: four repairs, and
  **`check.sh` — the oracle, which shares no code with this — reports the
  migrated directory clean**.
