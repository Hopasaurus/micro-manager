# T-0127 — GUI: render `refs` links

GUI task following the T-0104 spike (plan-board-links.md). **Gated on
T-0125/T-0126**: the spec defines the form, the validators pin the shape; the
GUI renders. No CLI change at all — `mm --edit --set refs:py:T-0012` and
`--unset refs` already reach unknown keys (op_update.go, usage OpEdit).

## Why

A `refs:` value is data on an item line; its purpose is to be *seen and
followed*. The GUI is the only component with a tree-wide view (discovery,
favorites, recent), which is why decision 4 of plan-board-links.md gives
resolution to the GUI and to nobody else — and why the missing/ambiguous
rendering must follow the §10 rule 5 policy (a favorite on an unmounted drive
is not a deleted project).

## What to build

- **Directory summary carries `board`**: the `/api/v1/projects/:projectId`
  summary (and `Directory` in the Go library) gains the declared slug, "" when
  absent. This is the lookup key: the GUI resolves a slug by scanning the
  directories it knows for a matching `board`.
- **Item rendering**: a `refs:` value on an item line renders each element as
  a link in the item panel (and on the card's detail surface), addressed by
  the target board's projectId and the target item's ID — routes keep
  projectId, links use the slug (decision 7). Nothing reconstructs a path from
  a slug; resolution is a lookup among known directories, exactly as projectId
  is resolved today.
- **Three resolutions, three renderings**: slug resolves → clickable link
  (`data-testid` includes the target board and item); slug resolves to
  nothing → the §10 rule 5 missing treatment (`data-missing="true"`), the
  element rendered as text, never a dead link; slug matches two known boards →
  rendered as ambiguous, both boards named, no guess (the `mm fix` tie
  discipline). A ref pointing at a renumbered item (mm fix in the target
  board, decision 6) renders as missing — the owned, documented cost.

## Verify

A harness board carries `board: py`; a second board carries an item with
`refs:py:T-0012`. Tests assert: the link renders clickable and resolves to the
target board's URI; removing the target board from the known set renders
`data-missing`; two boards declaring `board: py` render ambiguous with both
named. The web test suite and `go test ./...` stay green.
