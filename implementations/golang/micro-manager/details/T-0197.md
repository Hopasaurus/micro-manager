# T-0197 — GUI: the monthly Wake-up control cannot express last (spec-gui §5.6)

Found while wiring the Wake-up group in T-0173.

`spec-gui.md` §5.6's composition table says the monthly kind takes
`tickler-monthday` **"(required, `1`–`31` or `last`)"**, and the format's
`SCHEDULE` token has `last@08:00` — the last day of the month, which is the
whole reason the value exists. But the same section's DOM sketch fixes the
control as

```html
<input data-testid="tickler-monthday" type="number" min="1" max="31"
       name="tickler-monthday">
```

and a `type="number"` input cannot hold the string `last`. So a schedule the
format supports, the CLI accepts (`mm --add --tickler last@08:00`) and the
server's composer already handles is unreachable from the UI.

The server half is done and stays done: `composeTickler` passes `last` through
untouched and zero-pads everything else, and `prefillTickler` reads a `last`
schedule back into the control. Only the control cannot produce one.

## The decision to make

Whatever fixes this is a **spec change first** (§5.6's DOM sketch is the
contract a conformance suite reads), then a template change. Three shapes, none
obviously right:

1. Make `tickler-monthday` a `<select>` of 1–31 plus "last". One control, one
   testid, no new DOM — but it drops the number input the sketch names, and a
   31-option select is clumsy.
2. Keep the number input and add a sibling checkbox (`tickler-monthday-last`).
   A new testid in the contract, and two controls for one value.
3. Change the input to `type="text"` with a pattern. Keeps the testid and the
   shape, loses the browser's number affordances.

T-0173 shipped the spec's sketch verbatim rather than inventing DOM the
contract does not have; this item is where the choice gets made.
