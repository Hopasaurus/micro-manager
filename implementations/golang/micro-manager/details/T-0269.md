# T-0269 — Add informational stage comments to board.md

Generate stable informational comments between every declared stage run in version-2 board.md. Comments improve raw-file orientation but never determine membership; each item's stage: field remains authoritative. Include empty stages, regenerate comments during canonical regrouping, document compatibility/no-migration behavior, and test misleading or missing comments cannot affect parsed stage.

## Implementation

- Use `<!-- stage:SLUG -->` as the canonical marker and emit one marker for every declared stage, including empty stages.
- Regenerate the managed marker area on each real board mutation; repeated mutations replace markers instead of accumulating them.
- Preserve an undeclared-stage item defensively under `<!-- stage:undeclared -->` so formatting never silently deletes invalid data.
- Seed markers during initialization and v1-to-v2 migration. Existing v2 boards need no migration: readers already ignore comments, and their next real mutation adopts the layout.
- Document that comments are visual aids only and that each item's `stage:` field remains authoritative.

## Verification

- `go -C implementations/golang test ./...` passes, including CLI and web/SSE coverage.
- Tests cover ordered markers, empty stages, repeated mutations, misleading comments, initialization, and v1-to-v2 migration.
