# T-0108 — Saving settings gives an error: 'Origin "null" may not make state-changing requests here"

Full error:
Something went wrong
Origin "null" may not make state-changing requests here

## Notes

**2026-07-31** — Self-inflicted: the implementation set Referrer-Policy: no-referrer (its own addition - the spec never asks for it), and under that policy a browser strips the origin from NAVIGATIONS too, so a plain form POST to the service arrived with Origin: null and the 9.6 origin guard refused it. The header was defeating the check three lines below it. Changed to same-origin, which still leaks nothing cross-origin. Confirmed by controlled experiment in a real browser: no-referrer reproduces the exact error, same-origin saves. Also made the null-origin rejection explicit in originAllowed rather than incidental via url.Parse yielding an empty host.

TestReferrerPolicyDoesNotSuppressOrigin added - a Go test cannot send the header the browser sends, so the guard is on the policy itself. Existing null-Origin 403 case still passes. Verified live: settings now saves.
