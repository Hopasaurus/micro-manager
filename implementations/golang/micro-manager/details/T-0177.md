# T-0177 — Board resolution, pinning, and session/branch state

From [[project/spec-pi-mm-plugin.md]]. Spec §3.2 + §7: resolve through mm only (pin > MM_DIR passthrough > mm's own discovery), read directory.path from the first envelope and pin it; every later call passes --dir. Ambiguity (exit 3) surfaces candidates and requires a pin, never guesses. Also §3.2.1: mm_find lists located boards (in-use marked; empty is a result, not an error) and the board in use is always knowable — mm_board no-args returns path+project+how it resolved, mm_status names the directory, and the TUI keeps a persistent ctx.ui.setStatus board line (set at session start, on pin change, cleared when none). mm_board no-path is the full 'show me this board' view: identity + description + live status summary (§3.4). Pin travels in tool-result details per pi's state-management pattern and is reconstructed on session_start; branches get their own pin.
