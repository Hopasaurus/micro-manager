# T-0094 — Web API tests: canonicalize paths before comparing (F1: projectIDOf fails on macOS /var vs /private/var symlink paths)

Finding **F1** of `project/code-review-006.md` (CONFIRMED).

## The bug

`internal/web/api_handlers_test.go` compares raw paths:

- `projectIDOf` (line ~90): `if d.Path == path` — `path` comes from
  `t.TempDir()`, `d.Path` from `mm.Discover`, which **resolves symlinks**.
- line ~137: `strings.HasPrefix(d.Path, ts.Dirs[0])`.

On darwin `t.TempDir()` returns `/var/folders/…` but discovery returns
`/private/var/folders/…` — the comparison is never true, so `projectIDOf`
falls through to `t.Fatalf("discovery did not find %s", path)` and the whole
new test surface (a11y, about, api_handlers, audit, sse, testmode — 26 tests)
goes red. On Linux the paths coincide, so CI stays green and the defect is
latent.

The codebase already documents this exact hazard: `registry.go:405` on
`under()` says "Discovery returns resolved paths — on macOS `/var/folders/...`
comes back as `/private/var/folders/...`". The new tests just did not apply it.

## Fix

Canonicalize both sides with `mm.CanonicalPath` at both comparison sites.
Verified by the review: applying the patch turns the whole suite green on
darwin.

## Verify

- `go test ./internal/web/` green on a macOS machine (or a Linux box with a
  symlinked TMPDIR pointing through a resolved path, to simulate).
- The existing suite must stay green on Linux.

## Notes
