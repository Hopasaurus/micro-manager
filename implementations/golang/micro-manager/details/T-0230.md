# T-0230 — Columns M4: finish CLI/GUI/TUI surface, retire v1 mutation support

Milestone 4 of notes/add-columns-plan.md. Depends on M3. Generalizes the remaining CLI/GUI/TUI surface (--include-stage, per-stage --wip, dynamic GUI columns, state.<slug> theming), makes mutating ops refuse cleanly against any un-migrated v1 directory, and explicitly decides (migrate or deliberately keep as a v1 fixture) the fate of implementations/typescript/.micro-manager and sample-data/*. Full checklist: notes/add-columns-plan.md#m4.

## Notes

**2026-08-20** — From T-0235 (Columns M1f): three items belong here rather than a new M1 sub-task, since none block M2/M3 and all are operation-surface completion, exactly M4's remit. (1) op_update.go: neither setAnyField nor unsetAnyField has a 'stage' case, so --set stage:X currently fails with a confusing 'repeats field stage' parse error (safely refused by the transaction's reparse step, not data-corrupting) instead of a clear message or real support — deliberately not fixed in M1's sessions since routing a raw --set around --move's WIP-cap/tickler-drop/started-stamping logic is a real behavior question: does --set stage: get real support (duplicating --move's checks) or a clear refusal pointing at --move? (2) op_wip.go: SetWipLimit against a v2 directory just reports 'no working.NN.md file to count from' — harmless but not v2-aware messaging; worth doing alongside this milestone's own --wip generalization to per-stage caps. (3) --init still only creates version-1 directories; M2/M3 will want to decide whether --init needs a direct-to-v2 path or whether --init-then-migrate is the permanent story. Also: more v2 test fixtures beyond board_test.go/migrate_test.go/v2ops_test.go/tickv2_test.go/addmanyv2_test.go, parallel to sample-data/sample1-3, would help this milestone's own testing.

**2026-08-20** — From T-0228 (M2, proven against a scratch copy of the real live board): mm --status (human, --json, and porcelain forms — internal/cli/render.go and json.go both read st.Ready/st.Blocked/st.Someday directly) never reads mm.Status.StageCounts (added in T-0232), so against a real migrated v2 board it prints 'ready: 0, blocked: 0, someday: 0' regardless of actual counts. Same category as the --include-stage/per-stage --wip work already noted here — status rendering needs a v2 branch (loop StageCfg.Stages, print each with its label) the same way a future dynamic board view will.

**2026-08-20** — From T-0229's cutover: --start's confirmation message says 'started in slot N' (internal/cli render.go) unconditionally — v1-shaped wording that makes no sense once a directory has no slots at all. Same category/fix as the --status counts note above: needs a v2 branch in the relevant render func.

**2026-08-20** — From T-0229's cutover, a bigger item than the CLI display gaps above: check.sh (repo root) has zero version-2 support — it is entirely backlog.md/working.NN.md-shaped (board.md, stage:, reason:, tickler_dest: are all unknown to it). It's a real, separate reference implementation (used by find.sh and by mm's own oracle_test.go cross-validation, not just documentation), so porting it is comparable in scope to a chunk of this milestone on its own, not a quick fix. mm/oracle_test.go's TestValidatorAgreesWithCheckShOnTheRepository already dropped the now-v2 live board from its comparison list (legacy-v1 took its place) rather than waiting on this.

**2026-08-20** — Shipped this session ('CLI + library polish' slice, chosen via AskUserQuestion over GUI/check.sh/cross-directory-decisions): (1) --set stage:/--unset stage now refuse clearly for a v2 item, pointing at --move, instead of silently risking a duplicate-field line the transaction's reparse safety net would then refuse for a confusing reason. (2) SetStageWipLimit (op_wip.go/board_ops.go territory): --wip N --stage SLUG sets or clears (N=0) one stage's own wip.<slug> cap; refuses below current usage, refuses an undeclared stage, refuses on a v1 directory with a message pointing the other way too. (3) --status and its --json form now branch for v2: per-stage counts and labels (StageCfg.Stages order) instead of always-zero ready/blocked/someday; the human header's (wip N/M) becomes a list of only the stages that are actually capped, or omitted when none are. (4) --start's confirmation drops 'in slot N' for v2 ('T-0001 started' instead). (5) toJSONItem gained stage/reason/ticklerDest fields — found while fixing --status: every JSON-outputting operation (list, show, search, archive results) was silently omitting them for every v2 item, which is a bigger gap than the human-readable display one. (6) --add/--move/--pause gained --stage/--reason/--tickler-dest CLI flags — found while writing a test for (3): the LIBRARY has supported AddRequest.Stage/MoveRequest.Stage/PauseRequest.Stage since T-0227, but the CLI never read them, so mm --add TITLE --stage review would have silently landed on the default stage instead, and mm --move ID --blocked TEXT / mm --pause ID --blocked TEXT would have silently dropped the reason entirely for a v2 item. This was the largest and most important fix in this session — a silent-misrouting risk, not just a cosmetic one. (7) Confirmed TUI has zero implementation anywhere in the repo (only project/spec-tui.md) — that checklist item is genuinely a no-op. New/updated tests: v2ops_test.go (+4), wipv2_test.go (new, 10 tests). Full suite: mm + internal/cli 100% green; internal/web's GUI failures untouched, still real, still this milestone's own remaining scope. NOT done: GUI dynamic columns/theming (internal/web/board.go + mm.Section baked into the shared item/API model), check.sh's total lack of v2 support, mutating ops refusing cleanly against v1 (VersionMismatch, ErrVersionMismatch already exists but nothing raises it yet), and the implementations/typescript + sample-data/* per-directory migrate-or-keep-v1 decisions. Continuing this session with the cross-directory decisions instead (typescript/.micro-manager, sample-data/*).

**2026-08-20** — Cross-directory decisions (M4's last checklist item): sample-data/sample1-3, hidden, symbol, symbol-hidden all stay version 1, deliberately — documented in a new sample-data/README.md rather than left as silent inaction.
