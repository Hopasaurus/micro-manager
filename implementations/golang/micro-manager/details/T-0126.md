# T-0126 — Validators: `board` slug and `refs` shape

Validator task following the T-0104 spike (plan-board-links.md). **Gated on
T-0125**: the spec must define the `board` key and the `refs` LINKLIST before
the validators can agree on what is well-formed.

## Why

The spike's decision 4 — links are advisory, never load-bearing — sets the
exact line the validators stand on: they check the *shape* of `board` and
`refs` and nothing else. A stale or ambiguous link must never invalidate a
directory (resolution needs a tree-wide view a per-directory checker does not
have); a link that is *malformed* — not a LINKLIST, an element that is not
`SLUG:ID`, a slug that violates its shape — is a typo and a format violation,
exactly as a bad `tags` value is today.

## What to build

- **check.sh**: accept `board:` in `backlog.md` frontmatter, reject a value
  outside `[a-z][a-z0-9-]{0,15}`; validate `refs:` values on item lines as a
  LINKLIST whose elements each match `[a-z][a-z0-9-]{0,15}:[A-Z]{1,4}-[0-9]{1,15}`
  — same comma rule as tags, no spaces, no empty element. (This is where the
  reference checker's awk stands in for the whole format; keep the rule
  adjacent to the existing tags machinery.)
- **Go validator**: the same two rules in the same code path as `ParseTags` —
  a `ParseRefs`-style LINKLIST parser with the `SLUG:ID` element grammar;
  `board` validated against the slug shape in the `backlog.md` frontmatter
  pass. Message style must match the existing I7 vocabulary (`refs:…` names
  the bad element, not just the field).
- **Fixture**: `testdata/broken-refs/` — a board with a bad slug (`board: Py`
  — uppercase), a `refs` value with a space (`refs:py: T-0012`), and a
  non-ID element (`refs:py:twelve`) — each producing exactly one finding;
  registered in `brokenInvariants` (mm/fixtures_test.go) so the oracle test
  runs both validators over it and asserts lockstep. A clean fixture (`clean-*`
  name) carries a well-formed `board: py` and `refs:py:T-0012,go:T-0003` with
  zero findings — proof the validators do not check resolution.
- **Tests**: shape-only validation — a `refs` value pointing at a board that
  does not exist anywhere validates clean (advisory, decision 4); a malformed
  element fails exactly once. Both validators agree on every fixture.

## Verify

`go test ./...`, `go vet ./...`, `./check.sh --all` pass; the oracle test
asserts check.sh and the Go validator agree over `broken-refs/`; the fixture
corpus stays green.

## Update (post-ship)

Shipped 2026-08-02 (commit pending).

- **check.sh**: `isslug`/`isrefs` helpers beside `istags`; `board` captured
  from `backlog.md` frontmatter and shape-checked in the END block (next to
  the `project` check); `refs` validated on item lines next to the `tags`
  check; working-file frontmatter gains `refs` in the working-state checks
  and in the idle key list (a slot may now hold `refs: null`).
- **Go validator**: `Ref{Slug, ID}` + `ParseRefs`/`FormatRefs`/`validSlug`/
  `validGenericID` (mm/item.go); `refs` in the item-line field switch and in
  `fieldOrder` after `tags`; `board` shape-checked in the `parseBacklog`
  frontmatter pass; `refs` a registered working-file key (`workingItemKeys`,
  parsed like tags, emitted as `refs: null` when absent); `setAnyField`/
  `unsetAnyField` handle `refs` so `--edit --set refs=…`/`--unset refs` work.
- **AddRequest.Refs**: registered fields should be settable at add time, and
  a `refs` key smuggled through `Extra` would render in the wrong (Extra)
  position until the next parse. Mirrors `Tags`.
- **Fixtures**: `testdata/broken-refs/` (uppercase slug + space-in-link +
  non-ID element, nothing else — registered `"format"` in
  `brokenInvariants`) and `testdata/clean-links/` (valid `board: py` and
  `refs:py:T-0012,go:T-0003`, zero findings — proof resolution is never
  checked, the advisory rule). Oracle test runs both over both.
- **Tests** (`mm/refs_test.go`, 7): ParseRefs accept/reject matrix,
  empty→nil, dangling ref validates clean, malformed refs = one format
  finding naming the item line, bad `board` slug = one finding / good slug
  clean, refs survive start→frontmatter→pause round trip in canonical
  position, `Update{Set/Unset refs}` validates and refuses malformed input.
  Smoke: real binary `--edit --set refs=py:T-0012` → `--start` (refs rides
  into `working.01.md` frontmatter) → `--pause` (returns to the line), both
  checkers clean throughout.
- **Apostrophe trap**: a `checker's` inside the awk single-quoted program
  terminates the string and `bash -n` fails at the next `(`. Comments in
  check.sh avoid apostrophes.
- **Non-change**: no CLI switches for refs (plan decision: `--edit --set`
  suffices); links still never validated for resolution; the GUI work is
  T-0127.
