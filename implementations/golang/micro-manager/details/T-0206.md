# T-0206 — Tickler: warn at mm-ui startup when the service is disabled

From T-0204: mm-ui was running for days with the tickler service off and never said so; only the enabled path logs ("tickler service on"). When ticklerInterval() == 0, log a Warn at startup naming the config key tickler.interval and the two ways to enable it (system config interval; cron mm --tick), so a process that is supposed to move items but is not is never silent again. Test the startup path.

## Done (2026-08-07)

- `Start` now Warns `tickler service off` (key `tickler.interval`, help
  naming both enablement paths) whenever `ticklerInterval()` is 0; the
  enabled path keeps its `tickler service on` Info. The warning fires for
  both reasons an interval is absent: never configured, and set-but-invalid
  (already reported as a config warning at load, which the startup warning
  now pairs with its consequence).
- Tests through the real startup path (ephemeral port, real socket):
  `TestTicklerStartupOffWarns` asserts exactly one Warn naming the key and
  `mm --tick`, and no Info; `TestTicklerStartupOnLogsInfo` asserts exactly
  one Info with the interval and no Warn.
- Full `go test ./...` green; `check.sh` clean. T-0207's settings control,
  when it ships, should extend the help text (noted in details/T-0207.md).
