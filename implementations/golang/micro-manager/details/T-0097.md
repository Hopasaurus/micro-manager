# T-0097 — Publish a theme event when a project theme.json is deleted (F5: themeStamp zero short-circuits the disappearing case)

Finding **F5** of `project/code-review-006.md` (CONFIRMED).

## The bug

`internal/web/broker.go:166`:

```go
if mt := themeStamp(store); !mt.IsZero() && mt != lastTheme {
```

`themeStamp` returns the zero `time.Time` when `os.Stat` fails — i.e. when the
project's `theme.json` has been **deleted**. A user who deletes the file to
fall back to the system theme trips the `!mt.IsZero()` short-circuit before the
inequality is evaluated: no `theme` event is published and `lastTheme` is never
reset. Open tabs keep rendering the deleted theme's tokens until a manual
reload.

The appearing case works (zero → non-zero passes the guard); only the
disappearing case is dropped.

## Fix direction

Handle the missing-file state explicitly: when `themeStamp` is zero AND
`lastTheme` was non-zero, a deletion happened — publish the `theme` event and
reset `lastTheme` to zero. The guard must compare against a "was there a
theme" state, not against a zero `time.Time` alone.

## Note

F2 of the review (the `hx-target="#app"` dead swap) was fixed by T-0084, but
even with that in place a deleted theme never re-themes until this is fixed.
Both are required for theme refresh to work end to end.

## Notes

**2026-07-31** — themeStamp now returns (time.Time, bool) - the bool separates 'definitely absent' from 'could not stat'. Collapsing those into a bare zero time was the bug: the poller could not tell a deletion from a transient error, so it ignored both. poll publishes on any KNOWN change, which covers create, edit and delete; an unknown state leaves lastTheme alone rather than flapping an event every tick.

TestSSEThemeEventOnDelete added; verified it fails (10s timeout, no event) against the old guard.
