# T-0216 — Reload scan roots into the live UI registry

## Problem

Adding or removing a scan root in System Settings writes `scan.roots` to the system `config.json`, but the running UI continues to use the scan configuration captured when its registry was constructed. The saved root can disappear from the rendered settings page, and “Rescan now” still scans the old roots. Restarting `mm-ui` makes the saved configuration take effect.

## Root cause

`newRegistry` copies `opts.Config.Scan` into `registry.scan` at startup. After `POST /settings`, `SystemConfigReload` reloads only `s.opts.Config` and applies the tickler; it does not update `registry.scan` or invalidate the cached discovery result. Runtime-loaded roots also bypass the `~` and environment-variable expansion currently performed only by `cmd/mm-ui` during startup.

## Expected behavior

Saving scan-root changes should update the active registry immediately. A subsequent scan—including “Rescan now”—should use the new roots without a process restart, and the settings page should show the persisted configured roots.

## Suggested fix

- Give the registry a synchronized method to replace its scan configuration.
- Apply the same root expansion rules used at startup.
- Invalidate or refresh the discovery cache after scan settings change.
- Ensure both the settings form and config API reload paths call it.
- Add regression tests for adding and removing roots, rescan behavior, persistence across rendering, and `~`/environment-variable expansion.

## Relevant code

- `internal/web/registry.go`: `newRegistry`, `roots`, and the discovery cache.
- `internal/web/settings.go`: `saveSettingsSystem`.
- `internal/web/server.go`: `SystemConfigReload`.
- `cmd/mm-ui/main.go`: startup-only `expandRoots`.
