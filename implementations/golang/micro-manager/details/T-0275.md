# T-0275 — Implement a CodeMirror Markdown editor for item detail

Replace the plain item-detail editing experience with a progressively enhanced CodeMirror 6 editor configured for Markdown source. T-0272 owns rendered Markdown view/preview; this task owns the source editor and its lifecycle.

## Selected implementation

Use CodeMirror 6 with a deliberately minimal, version-locked bundle, following the research in T-0274.

- Include only editor state/view, Markdown language support, history, search, bracket matching, soft wrapping, and the normal accessible keymap.
- Do not include autocomplete, linting, language servers, workers, minimaps, folding, multiple files, or Vim bindings in this task.
- Vim support is a separate follow-up so the base editor can ship and be measured independently.
- Keep the existing textarea in the form as the canonical raw Markdown value, submission control, and no-JavaScript fallback. CodeMirror is an enhancement, never a second source of truth.

## Vendoring and build

- Add a small deterministic asset-build directory with a lockfile and one entry module.
- Pin every CodeMirror package to an exact version.
- Produce one self-contained, minified browser artifact under `internal/web/static/`, where Go embeds it into the binary. Runtime CDN or network access is forbidden.
- Check in the generated bundle, upstream version/source manifest, checksum, MIT license notices, and the exact rebuild/update command.
- Load the local bundle before `mm.js` and expose only a small application-specific factory/lifecycle API.
- Record compressed and uncompressed bundle sizes in the task results so later optional features can be evaluated against a baseline.

## Editor behavior

- Enhance `textarea[data-testid="item-field-detail"]` only after JavaScript and CodeMirror initialize successfully; otherwise leave the textarea visible and usable.
- Seed the editor from the textarea and synchronize every CodeMirror document change back to `textarea.value` so ordinary form submission remains unchanged.
- Use Markdown syntax highlighting and soft line wrapping. Do not show line numbers by default; prose benefits more from panel width.
- Enable undo/redo, search, standard platform editing shortcuts, bracket matching, and browser spellcheck where CodeMirror supports it without changing Markdown bytes.
- Preserve exact source, including line endings where the existing form does so. Highlighting and editor state must never be submitted.
- Integrate with T-0272's Edit/Preview switch: preview consumes the synchronized textarea value. Returning to Edit restores the document, selection, focus, scroll position, and undo history where practical.
- Save continues through the existing form route, expected revision, and concurrent-edit conflict path. A successful save returns to T-0272's rendered view.

## Lifecycle and htmx

- Initialize at most one editor for a live item panel.
- Destroy the editor view and remove listeners before htmx removes or replaces its panel.
- After an htmx settle, initialize only when the replacement panel is in Edit mode.
- Closing the panel, navigating to another item, saving, resolving a conflict, or receiving an SSE-driven replacement must not leave a detached editor or overwrite newer DOM with stale editor state.
- Reuse existing focus-restoration conventions. Entering Edit focuses the editor at a predictable position; returning from Preview restores the prior selection.

## Styling and accessibility

- Map background, foreground, selection, caret, syntax tokens, borders, and focus rings to existing `--mm-*` theme variables; verify all bundled themes.
- Keep a programmatic label tied to the editor and preserve the detail field's help/error association.
- Do not trap Tab by default without an accessible escape/toggle. Document any CodeMirror Tab behavior exposed to users.
- Test keyboard-only operation, screen-reader naming, visible focus, zoom/reflow, high contrast, reduced motion, IME composition, paste, and touch/mobile input in real browsers where jsdom cannot establish behavior.

## Acceptance coverage

- With JavaScript disabled or bundle initialization forced to fail, the original textarea remains functional.
- Editing in CodeMirror updates the submitted textarea exactly; server persistence is byte-for-byte the Markdown the user edited.
- Initial load, Edit/Preview round trips, validation errors, concurrent conflicts, htmx swaps, SSE updates, item changes, and panel close preserve or intentionally discard state according to the existing UI contract.
- Markdown headings, emphasis, lists, links, fenced code, inline code, blockquotes, tables, task-list text, and raw HTML source receive sensible highlighting without altering content.
- Search, undo/redo, selection, paste, composition, soft wrapping, and large-document behavior have behavioral coverage.
- No runtime network request, worker, eval, inline script, or CSP relaxation is introduced.
- The full Go suite, the real `mm.js` Node/jsdom suite, asset embedding tests, and browser-level smoke/accessibility tests pass.

## Dependencies and boundaries

- Coordinate markup and mode state with T-0272, but do not duplicate its `markdown-it` rendering logic inside CodeMirror.
- The follow-up Vim task may add `@replit/codemirror-vim`; this base task must expose a clean optional-extension point without depending on that package.
- Board data and `structure.md` are unchanged. This is presentation/editing infrastructure only.

## Defaults chosen during refinement

- CodeMirror bundling is accepted by selecting CodeMirror; generated assets remain checked in so ordinary Go builds need no Node installation.
- No line numbers initially.
- Standard keybindings, search, soft wrap, and spellcheck initially; Vim is separate.
- No arbitrary editor plugins beyond the pinned minimal set.
- Measure large-detail performance during implementation and choose the native-textarea fallback threshold from those results rather than setting it in advance. Record the tested sizes, timings, browser, machine context, and selected threshold.
- Preserve the existing panel-close behavior. Unsaved editor state does not gain new session persistence: closing and reopening follows the same discard behavior as the current textarea.

## Open questions

None at refinement time. Performance measurement may identify a threshold or browser-specific issue during implementation, but that is an implementation result rather than a pending product decision.
