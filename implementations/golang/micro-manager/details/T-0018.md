# T-0018 — Implement start with slot selection and WIP enforcement

## Context

The WIP limit is the count of `working.NN.md` files. Because each holds at most
one item, the limit is enforced structurally — there is no counter to check.

## Requirements

- Without `--slot`, use the **lowest-numbered idle slot**.
- With `--slot NN`, fail with `ErrPreconditionFailed` if that slot is occupied
  or does not exist.
- Copy every field verbatim into the slot frontmatter, including unregistered
  ones and `detail:`. Format spec §5.2 gives both places the same lexical form,
  so this is a copy and never a conversion — `tags:infra,ci` stays exactly that.
- Set `status: working` and `started:` to today. Leave body sections empty except
  `## Task`, seeded with the title and a link to the detail file if present.
- Write the working file **before** removing the backlog line (see
  [T-0012](T-0012.md)).

## The rule that matters

**If every slot is occupied, fail with `ErrWipLimitReached`. Do not create a new
working file to make room.** Creating one silently raises the WIP limit, which
is the single thing the limit exists to prevent.

The error must name: the limit, what currently occupies each slot, and the three
ways forward — finish something, pause something, or raise the limit
deliberately with `--wip`. This is why `ErrWipLimitReached` is separate from
`ErrConflict`: it is the one error with a routine, expected remedy, and the
message is most of its value.

## What was decided while implementing

Three things the spec left to the implementation:

- **Unregistered fields ride in the slot frontmatter as extra keys.** §5.1.8
  requires them to transfer verbatim and §9 makes unknown frontmatter keys valid
  and ignorable, so this is the only representation that loses nothing and
  changes nothing for another reader. It follows that idling a slot must delete
  every key that is not `doc`, `version` or `status`, or the next item to occupy
  the file inherits the last one's fields.
- **A reserved key (`id`, `status`, `next_id`, `doc`, `version`) as an
  unregistered field is refused** with `ErrInvalidArgument` rather than dropped.
  It cannot be written into the frontmatter without colliding with the file's own
  key, and dropping it silently would destroy the data this path exists to keep.
- **`blocked:` does not travel into the slot; its text is seeded into
  `## Blockers`.** Carrying the field would put it back on the line at `--pause`
  time in `## Ready`, which I5 forbids — and the reason is still worth having in
  front of whoever picks the work up.

Body prose outside the four sections is left alone, so a slot whose template
says "Nothing in progress" still says it while occupied. Deleting prose the tool
did not write is worse than leaving it; `--init` (T-0022) should not generate
that sentence in the first place.
