# T-0116 — check.sh and the Go validator agree on the declared ID grammar (fixture corpus)

Fourth task of the T-0112 spike. Depends on T-0113 and T-0114.

## Today

- check.sh hardcodes the grammar in several places: `next_id` must match
  `/^T-[0-9][0-9][0-9][0-9]$/` (line ~329), and I1/I2 parse item IDs the same
  way.
- The Go validator (mm.Validate) has a test asserting it agrees with check.sh
  over the real directories and a deliberately broken one.

## What to change

- check.sh reads `id_prefix`/`id_width` from backlog.md frontmatter and
  validates `next_id` and every ID per the declared grammar (defaulting to
  today's behavior when absent).
- The Go validator mirrors it; the agreement test must cover a non-default
  directory.
- The fixture corpus (`testdata/`, `sample-data/`) gains a directory with a
  non-default prefix and width — e.g. `X-` + 3 digits — plus a deliberately
  broken variant (an ID that violates the declared grammar) so both validators
  are exercised both ways.

## Verify

`./check.sh --all` is clean with the new fixture; the broken variant reports
the same violation from check.sh and the Go validator.

## On hold (2026-08-01)

Paused while T-0119 decides the width limits. The work done so far is complete
and tested: check.sh reads `id_prefix`/`id_width` and matches every ID by
token; the corpus gained `testdata/clean-id-grammar` (X/3), `testdata/broken-id-grammar`
and `sample-data/sample3` (MM/3); the oracle test covers a non-default
written directory; the whole suite and `./check.sh --all` are clean.

The one open question was the pathological width edge; T-0119 answered it: a
shared cap of 15 digits (10^15 − 1 < 2^53, the double-exactness limit of the
narrowest reader). The decision is in
`project/plan-id-widths.md`; T-0120 lands it in §3.3.2, and this task then
enforces the cap in check.sh and the Go validator, which is what removes the
mawk/Go divergence at width 16+.

## Cap enforcement landed (2026-08-01)

T-0120 landed the spec change; this task enforced it on both sides:

- check.sh's `resolve_grammar` rejects a width above 15 as a violation
  ("above the 15-digit cap"), keeping 1–2 and 7–15 as warnings and 3–6 as
  RECOMMENDED.
- The Go validator's `ParseIDGrammar` rejects `w > 15` the same way, with the
  default grammar standing in so the rest of the directory still parses.
- `Init` refuses `IDWidth > 15` — a writer must not create a directory the
  checkers reject.
- The corpus gained `testdata/broken-id-width-16`: a directory declaring
  `id_width: 16` whose IDs are in the standing-in default grammar, so the
  width finding is its only one. Both validators report exactly
  `backlog.md:6`.
- Tests: `TestWidthAboveCapIsAViolation` (16 is a violation, never a
  warning), `TestWidthAtTheCapIsAccepted` (15 is the inclusive edge, with
  `Cap() = 10^15 − 1`), and `TestInitValidatesGrammar` covers `IDWidth: 16`.

The pathological-width divergence is gone: at 16+ both validators refuse
uniformly instead of Go rejecting while mawk accepted.
