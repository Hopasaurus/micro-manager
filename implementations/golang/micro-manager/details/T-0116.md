# T-0116 — check.sh and the Go validator agree on the declared ID grammar (fixture corpus)

Fourth task of the T-0112 spike. Depends on T-0113 and T-0114.

## Today

- check.sh hardcodes the grammar in several places: `next_id` must match
  `/^T-[0-9][0-9][0-9][0-9]$/` (line ~329), and I1/I2 parse item IDs the same
  way.
- The Go validator (mm.Validate) has a test asserting it agrees with check.sh
  over the real directories and a deliberately broken one.

## What to change

- check.sh reads `id_prefix`/`id_width` from backlog.md frontmatter and
  validates `next_id` and every ID per the declared grammar (defaulting to
  today's behavior when absent).
- The Go validator mirrors it; the agreement test must cover a non-default
  directory.
- The fixture corpus (`testdata/`, `sample-data/`) gains a directory with a
  non-default prefix and width — e.g. `X-` + 3 digits — plus a deliberately
  broken variant (an ID that violates the declared grammar) so both validators
  are exercised both ways.

## Verify

`./check.sh --all` is clean with the new fixture; the broken variant reports
the same violation from check.sh and the Go validator.
