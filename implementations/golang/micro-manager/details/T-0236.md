# T-0236 — VersionMismatch: scope how v1-mutation tests validate correctness once --add/--start/--pause/--finish/--move/--edit/--remove refuse against v1

One item of T-0230's remaining checklist (notes/add-columns-plan.md#m4), split out as its own task since it's a real architectural decision, not a quick fix.

spec-tools.md §5.3.4's longevity policy: `--add`, `--start`, `--pause`, `--finish`, `--move`, `--edit`, and `--remove` SHOULD refuse against a directory below the current version with `VersionMismatch` (§6.3, ErrVersionMismatch already exists in mm/errors.go, unused). Straightforward to say, but sizing it (2026-08-20 session) found the real blocker: **~212 call sites across 27 test files** in the `mm` package call these exact methods against v1 fixtures today and expect them to succeed — essentially the entire pre-v2 test corpus, which predates T-0227's v2 work and has been stable since before this redesign began.

Implementing the refusal unconditionally in the library would break nearly all of it. The open design question: once `Store.Add`/`Start`/`Pause`/`Finish`/`Move`/`Update`/`Remove` refuse against v1, how do the ~212 existing call sites keep validating v1 mutation-logic correctness (which is still real and still needed — v1 directories still exist, in sample-data/ and possibly implementations/typescript/, and `--check`/`--migrate` still have to interpret them correctly)? Candidate directions, none decided:

- Test through a lower-level/internal path that bypasses the public refusal (e.g. unexported helpers the public methods currently call directly), keeping the refusal itself as a thin wrapper at the public API boundary
- Accept that v1-mutation-logic tests move to testing the migration step's *input* correctness instead (i.e. "does migrate correctly read this v1 shape"), and retire direct v1-mutation-method tests as no-longer-representative of any real, reachable code path
- Something else — this needs a real design pass, not a guess

Whatever the answer, it needs to preserve real coverage of v1 correctness, not just make the test count green by weakening what's actually tested.

See T-0230's own detail file for the rest of M4's remaining scope (GUI, check.sh, cross-directory decisions).
