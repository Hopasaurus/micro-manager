# T-0057 — Render the item panel, the item form and the add-item panel

## As built

`internal/web/item.go`, `templates/item.html`.

**One template serves both panels.** `/p/:id/new` is the same panel in the same
position with an empty form, which is what §4.1 means by putting it there rather
than giving it a view of its own.

**A direct load renders the board behind the panel.** §5.6 requires the board to
remain in the DOM; an htmx swap fetches only `item-panel`, but a bookmarked
panel URI has to produce both. That needed a `withData` template helper, because
two things on one page each expect to be `.Data`.

**`board` and `column` moved into `partials/`.** A page can only reach templates
its own set carries, so the item page could not see a definition that lived in
`board.html`. Anything more than one page renders belongs in partials.

**The slot body is parsed in the web layer.** `## Plan` and `## Notes` are the
human half of a working file and no library operation reads them. Pushing a
parser into `mm/` for one caller would have put presentation in the library;
`parseSlotSections` stays here.

**Form values distinguish absent from empty.** `formValue` returns a second
`ok`, and `UpdateRequest` takes pointers, so clearing a field is a different
request from not touching it. Without that, opening the panel and saving would
quietly blank whatever the form did not carry.
