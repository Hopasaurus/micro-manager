# T-0273 — Enable viewing and updating structure.md from UI

Add a project-scoped guide for viewing and safely maintaining `structure.md`
without weakening the explicit-refresh and user-note protections introduced by
T-0264.

## Proposed location and navigation

- Add `GET /p/:projectId/structure` as the project guide page.
- Put a persistent **Guide** link in the project navigation so the primarily
  read-oriented page is discoverable without opening Settings.
- Add a **Project guide** section to `/p/:projectId/settings` that links to the
  guide and exposes its maintenance status. System settings must not show it.
- Keep editing and refresh controls on the guide page. Settings is an entry
  point, not a second editor with independent behavior.
- Version-1 projects show a migration-required state and link to project
  settings; they must not offer version-2 structure editing or refresh.

## Viewing behavior

- Render the complete current `structure.md` using the locally vendored,
  HTML-disabled Markdown renderer from T-0272. Do not add another Markdown
  implementation or allow raw HTML execution.
- When the file is absent, show a clear empty state and an action to create the
  current guide through the existing explicit refresh operation. Merely opening
  the page must not create or modify a file.
- Show whether refresh is allowed, protected, or unavailable. A checked and
  otherwise valid refresh marker means allowed; an unchecked, deleted,
  duplicated, or malformed marker or malformed note boundaries means protected,
  matching `Store.RefreshStructure` rather than duplicating looser UI rules.
- Show the file's last-observed revision so an update can detect concurrent
  filesystem edits.

## Updating user content

- Editing is intentionally limited to the delimited user-note region. Do not
  offer a raw whole-file editor: generated guidance, the board description,
  refresh marker, boundaries, and frontmatter remain outside the editor.
- Provide Edit and Preview modes for the content between
  `<!-- mm:user-notes:begin -->` and `<!-- mm:user-notes:end -->`.
- Use the CodeMirror Markdown editor introduced by T-0275 for editing the
  user-note region. Keep its underlying textarea as the canonical submitted
  value and no-JavaScript or initialization-failure fallback; do not create a
  separate editor implementation for this page.
- Reuse T-0272's raw-textarea-as-source-of-truth pattern and Markdown preview.
  Saving must persist the entered Markdown bytes inside the boundaries without
  submitting rendered HTML.
- Update the note region with a library operation and the normal transaction
  envelope: reload, verify the expected revision and exact single ordered
  boundary pair, splice only the bytes inside the boundaries, validate where
  applicable, and commit atomically. A conflict or malformed file changes no
  bytes and leaves the user's draft available for recovery.
- Do not rewrite generated guidance, the description, refresh marker,
  frontmatter, line endings outside the note region, or unrelated bytes as a
  side effect of saving notes.
- Treat an absent file as having no editable note region; guide creation remains
  an explicit refresh action rather than an implicit consequence of Save.

## Explicit refresh from the UI

- Provide **Refresh generated guide** only for version-2 projects. It calls the
  existing `Store.RefreshStructure` operation and therefore preserves the board
  description and user-note region byte-for-byte.
- Require confirmation because refresh replaces all managed content outside the
  preserved areas. Explain exactly what is preserved before the user confirms.
- If the opt-in marker or boundaries protect the file, disable or reject refresh
  with the operation's reason and instructions: restore exactly one checked
  marker and valid boundaries, or rename the protected file before creating a
  new guide.
- On success, re-read and re-render the file. Report created, updated, and true
  no-op outcomes distinctly. Refresh must never run automatically on page load,
  save, migration, or another settings change.

## API and UI contract

- Extend `spec-tools.md` with the narrow user-note update library operation;
  `RefreshStructure` remains the only generated-content update operation.
- Extend `spec-gui.md` with the guide route, navigation/settings entry points,
  stable test IDs, page states, confirmation dialog, and conflict/error
  behavior before implementation.
- Use project authorization/path resolution already used by other project
  routes. Never accept a client-supplied filesystem path.
- Use POST for note save and refresh actions, retain existing CSRF/request-size
  conventions, and support ordinary form submission when JavaScript is absent.

## Acceptance coverage

- A valid file renders as Markdown; raw HTML and unsafe links remain inert.
- A missing file is not created by viewing it and can be explicitly created by
  refresh.
- Editing and previewing notes preserves unsaved source; save changes only bytes
  inside the delimiters.
- Refresh preserves the description and note bytes and reports create, update,
  and unchanged results correctly.
- Unchecked, missing, duplicated, or malformed opt-in markers and missing,
  duplicated, or reversed note boundaries protect the file from refresh.
- Stale revisions, external edits, malformed files, oversized input, read-only
  files, and write failures produce actionable errors without partial writes or
  lost drafts.
- Project navigation and project settings expose the guide; system settings and
  version-1 projects do not expose invalid update controls.
- Full Go, JavaScript behavior, route, DOM-contract, CSP, keyboard, responsive,
  and no-JavaScript tests pass.

## Migration and compatibility

No board-format migration is required. `structure.md` remains optional,
non-authoritative documentation. Existing protected or hand-edited files remain
untouched until the user explicitly saves notes or requests refresh, and each
operation must honor the existing protection contract.

## Decisions from refinement

- The original update requirement primarily meant exposing the recently added
  explicit structure-refresh operation in the UI. Editing is also included
  because project-specific notes are useful, but it is restricted to the
  delimited user-note region.
- **Guide** is a persistent project-navigation item, with Project Settings also
  providing a link and maintenance status.
