# T-0120 — Spec: bound id_width at 15 in spec-file-format.md (§3.3.2)

Spec change task following the T-0119 spike. The spike's decision is in
`implementations/golang/project/plan-id-widths.md`; this task lands it in the
normative spec. **The format spec is normative: the validators (T-0116) cannot
enforce the cap until this task defines it.**

## What the spec says today (§3.3.2, as landed by T-0113)

- `id_width`: "one or more ASCII digits", default 4; 3–6 RECOMMENDED, warn
  (never fail) outside.
- Counter space `10^W − 1`; no upper bound on W.
- Rule 3: a reader that cannot honor the declared grammar MUST refuse loudly,
  never silently misparse.

## What T-0119 decided

1. "Without special libraries" = no third-party dependency; standard-library
   bigints (JS `BigInt`, `java.math.BigInteger`, Go `math/big`) count as native.
2. **The shared cap is 15**: every implementation must accept and compare
   exactly any width 1–15, because `10^15 − 1 < 2^53` — the double-exactness
   limit of the narrowest reader (check.sh's mawk, JS `number`). At 16 digits
   both mawk and JS `number` silently round (measured: `9999999999999999`
   becomes `1e16`), and Go's `Cap()` overflows int64 at width 19.
3. Widths above 15 are a format violation everywhere — the uniform refusal that
   removes the T-0116 divergence (Go rejected 20+ while mawk accepted).

## What to change in spec-file-format.md

- §3.3.2 table + rules: `id_width` is "one to fifteen ASCII digits" (default 4);
  keep the RECOMMENDED 3–6 warning band *within* 1–15; state that a width above
  15 is invalid (a reader MUST refuse, per rule 3 — the cap is exactly where the
  simplest reader stops being exact).
- The `10^W − 1` counter-space note generalizes with the bound: "for W ≤ 15".
- §5.1 table + paragraph and Appendix A repeat the ID form; reconcile them with
  the bound, and note the reference implementation's mawk arithmetic as the
  binding reason.
- Leave the default grammar (absent fields) byte-identical: `T` + 4.

## Verify

A reader of the spec can state the three-band ladder without ambiguity:
widths 1–2 warn, 3–6 recommended, 7–15 warn, 16+ invalid. T-0116 then enforces
the same ladder in check.sh and the Go validator.

## Referenced by

T-0116 (validators enforce the cap), T-0117 (GUI), T-0118 (per-prefix
counters, which divide the same space).
