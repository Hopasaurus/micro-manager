# T-0252 — New-item panel: autofocus the title field on open

Requested: when a new item is being created, focus should land in the title
field automatically, so typing can start with no click first.

## Fix

- `internal/web/templates/partials/item-panel.html`: the title `<input>`
  gets the HTML `autofocus` attribute when `$d.New` — the no-JS/direct
  page-load path (`GET /p/:id/new`).
- `internal/web/static/mm.js`: `autofocus` alone is not reliable once the
  panel is inserted client-side after the initial document load (browsers'
  "autofocus processed" flag is per-document and can already be spent by the
  time an htmx swap injects it), so a `focusTitleForNewItem()` function
  explicitly focuses `[data-testid="item-panel"][data-new="true"]
  [data-testid="item-field-title"]`, wired to the same `htmx:afterSwap` /
  `DOMContentLoaded` pair `applyPanelWidth` (T-0242) already uses — the panel
  can appear from a direct load, an htmx-swapped add link, or "save and add
  another"'s OOB reopen (T-0080), and this covers all three. `data-new`
  distinguishes a fresh item from an edit, so opening an existing item's
  panel never steals focus. Calling `.focus()` on an already-focused element
  is a no-op, so re-running this on an unrelated swap while the panel stays
  open is harmless.

## Spec

`spec-gui.md` §11 (Accessibility) gained a numbered requirement: the item
panel MUST focus its title field when opened for a new item, and MUST NOT
when opened for an existing one.

## Tests

`internal/web/jstest/mm.test.js`: three new tests — the new-item panel
focuses its title field on a direct load, focuses it after an htmx swap
(simulating the add-link path), and an existing-item panel does not steal
focus. `internal/web/dragdrop_test.go`'s `TestDragAttributesArePresentInTheClient`
line-count guard bumped from 1010 to 1030 for the added client code (a real,
justified addition, not drift).

Verified live: built a scratch v2 board, ran `mm-ui` against it, clicked
Ready's "+" in a running browser, and confirmed `document.activeElement` was
the title field immediately after the swap.

`go build`, `go vet`, `gofmt -l`, and the full `go test ./...` (mm,
internal/cli, internal/web including the jstest node suite) are all green.

## Notes

Title field autofocuses when the new-item panel opens, both from a direct page load and after an htmx swap; existing-item panels are untouched. Verified live in a running browser.
