# T-0141 — Drag and drop fails a lot

Spike: analyse why drag and drop fails, mostly on upward moves, and create tasks
to fix. Outcome: one root cause found, reproduced in a real browser, fix
validated; follow-up filed as [[T-0149]].

## Reproduction

Headless Chromium (Playwright) against a scratch six-item Ready column, driving
real pointer events. Dragging the bottom card up to the top and releasing with
the pointer in the top card's upper half: **no `drop` event fires at all** —
`dragend` arrives directly, no request is issued, no toast, and the board is
unchanged. Downward drops in the same geometry fired and reordered correctly.

Instrumented event log (bubble-phase listener reading state after mm.js's own
handler), dragging T-0006 up to y=129, card height 77 px, pitch 85 px:

```
dragover y=152 idx=1 phTop=185 phH=32 target=mm-item__menu   <- ph between cards 1 and 2
dragover y=129 idx=0 phTop=100 phH=32 target=mm-item__prio   <- ph at column top
dragend  y=129                                               <- mouseup: NO drop
```

The final dragover computed the right index (0 — the column top) and put the
placeholder at the top (100..132). The pointer at 129 was *over the placeholder*.
The drop was lost.

## Root cause

The placeholder is a normal flex child of the column body, 32 px tall in an 8 px
gap, so inserting it shifts every card at or below the insertion point down by
32 px. `hoverTarget` re-inserts it on every dragover (the T-0110 fix removes it
before measuring, then puts it back). The release therefore goes like this:

1. The browser hit-tests the last dragover and records the card under the
   pointer as the drop target.
2. mm.js's handler then inserts the placeholder, which **shifts that card away
   from the pointer**.
3. On mouseup the browser's cached drop target no longer sits under the
   pointer, so the `drop` event is delivered nowhere. Silent no-op.

The geometry is direction-dependent, which is exactly what the reporter saw:

- **Dragging DOWN**: the insertion point is below the pointer, so the card
  under the pointer (above the placeholder) does not move — drops fire.
- **Dragging UP**: the insertion point is at or above the pointer, so the card
  under the pointer shifts away at the instant of release — drops are lost.

Aiming at the gap between two cards — the natural target for a reorder — puts
the pointer on the placeholder itself, so the strongest visual "drop here"
signal is precisely where the drop dies. (T-0110's fix made *measurement*
placeholder-free but left the placeholder in flow, which is what T-0141 found.)

Secondary, latent: the drop trusts the last dragover's index. The browser
coalesces dragover to frame rate, so a release within one frame of a fast final
move could commit a stale index. Not reproduced with synthetic events (they are
not frame-timed); cheap to defend against.

## Validated fix

Make the placeholder **out of the column's flow**, plus a defensive re-derive:

1. `mm.css` — `.mm-column__body { position: relative }` (anchor) and
   `.mm-drop-placeholder { position: absolute; left: 0; right: 0;
   pointer-events: none }`. Out of flow, inserting or moving the placeholder
   never shifts a card, so the browser's drop target stays under the pointer
   and the drop always fires. `pointer-events: none` sends drag and drop events
   to the card/body behind the placeholder (the marker itself is removed and
   re-inserted on every dragover, so it must never be the target).
2. `mm.js` `hoverTarget` — append the placeholder, then set `style.top` to the
   insertion point computed from card rects (top for index 0; midpoint of the
   neighbouring cards' gap for 0 < i < n; below the last card for append).
3. `mm.js` `drop` handler — re-derive `move.index` from the drop event's own
   `clientY` before `commitMove()` (guards the frame-coalescing race and makes
   the drop position authoritative).

Verified in the browser against the scratch board:

- 11/11 intra-column drops (top, upper/lower halves, both boundaries, bottom;
  both directions) landed at exactly the pointer's index, on screen and on
  disk.
- Cross-column ready → someday append works.
- Keyboard move mode (Space, ArrowDown, Enter; Escape cancels) works.

## Tests affected by the fix

- `TestDropIndexIsMeasuredWithoutThePlaceholder` (T-0110's source-shape guard)
  becomes vacuous: with the placeholder out of flow the cards never shift, so
  "clear before measuring" is trivially satisfied. Re-express the guard as
  "the placeholder is positioned absolutely, out of flow" (assert on mm.css and
  the JS `style.top`).
- `TestDragAttributesArePresentInTheClient` — the 700-line mm.js guard. The
  validated fix (with comments) measures 719 lines; the fix task must either
  trim it back under 700 or justify raising the guard.
