# T-0179 — Write tools: mm_add, mm_edit, mm_move, mm_note, mm_init, mm_describe

From [[project/spec-pi-mm-plugin.md]]. Spec §4.2 + §3.3: mm_add reports the assigned ID; mm_edit reaches unregistered keys via --set and never replaces wholesale; mm_move keeps position semantics; mm_note appends the dated entry; mm_init creates a board (project required; dir/slots/slot_width/description) and pins it. mm_init's prefix parameter sets the board's id_prefix via --prefix P (validated against the 1-4 uppercase letter grammar) and MUST gate on the installed build's --prefix support (exit-2 degradation) — spec-tools.md §5.1.1 does not name --prefix yet; that gap is T-0186. mm_describe writes the board description's first paragraph through mm --describe, never by touching structure.md directly (spec §3.4; the CLI op is T-0187). Each tool is one mm subprocess, one transaction.

## As built

`plugins/pi-mm/src/tools-write.ts`, sharing the read set's `operate()` so the
gates, the `--dir`, the error mapping and the `details` shape stay decided once.

- **`mm_add` leads with the ID.** "The new item INCLUDING its ID — the handle
  for everything after" is the tool's whole contract, so the formatted line
  starts with it, and the changed files follow.
- **`mm_edit` reaches unregistered keys** through `--set KEY=VALUE`, refusing a
  pair without an `=` before spending a subprocess, and refuses an edit that
  names nothing to change. It never rewrites an item wholesale — only the
  fields named.
- **`mm_move` takes exactly one destination.** The CLI refuses two as well;
  catching it here spends no subprocess and names both, which is the more
  useful error.
- **`mm_init` is the one tool that does not resolve a board first** — it is
  what you call when there is none, and `--dir` names where the new board goes
  rather than which one to act on. It pins what it creates, reading the
  identity from `result` (the envelope shape T-0176 found).
- **The prefix is validated against the format's grammar before invocation**
  (§3.3), so a bad one gets a message about uppercase letters rather than about
  a switch, and costs nothing.
- **Build gating is exit 2, not sniffing.** `--describe`, `--init --prefix` and
  `--init --description` are switches a minimally conforming build need not
  have. The plugin runs the operation and lets the runner's exit-2 message
  ("not available in the installed mm build") do the work — one fewer thing to
  keep in step with the CLI, and there is no fallback that writes
  `structure.md` itself (§3.4, §8.1).

## Two things the tests found

**The gate order was wrong.** `mm_move` validated its parameters before asking
whether `mm` existed, so a user with no `mm` got "mm_move needs a destination"
— two round trips to reach the actionable message. Every tool now calls
`ready(deps)` first: the environment failure is the more fundamental one, and
it is the same answer whatever the arguments were.

**`mm_show` was dropping unregistered fields.** The contract test set
`owner=dana` through `mm_edit` and then could not find it in `mm_show` —
`itemDetail` rendered only the registered fields. The format's whole extension
point is keys a tool has never heard of, so a view that hides them makes the
plugin lossy about the thing the format exists to protect. `ItemView.extra` is
now carried and printed.

Both were caught by tests written from the spec rather than from the code,
which is the argument for writing them that way.

## Verification

`src/tools-write.test.ts` asserts the argv each tool builds (what actually
reaches the board), what each refuses before spending a subprocess, and the
text the spec fixes. `src/mm-contract.test.ts` then drives init → add → edit →
move → note → describe → check against a **real board and a real `mm`**,
including the round trip that proves an unregistered key survives, and the real
`--describe` degradation (this build has no such switch, so the tool takes the
exit-2 path for real). It skips when `mm` is absent.

75 tests: all pass with `mm` on PATH, 72 pass and 3 skip without. `tsc --noEmit`
clean.
