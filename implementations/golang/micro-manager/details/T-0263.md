# T-0263 — Add shell-interpolation safety note to CLI help

## Context

CLI help should warn users that backticks and `$()` inside shell command arguments may be evaluated by the shell before `mm` receives them. Examples involving notes, descriptions, detail text, titles, or arbitrary field values can therefore behave unexpectedly or execute commands unless quoted safely.

## Requirements

- Add a concise warning in the relevant help text about backticks and shell command substitution.
- Show a safe quoting example appropriate to supported shells without implying that one quoting form is portable everywhere.
- Review existing help examples for interpolation hazards and correct any unsafe examples.
- Add or update help-output tests so the warning and safe example do not regress.
- Keep the guidance about shell behavior distinct from `mm` parsing or validation behavior.

## Done when

The relevant CLI help clearly explains the risk, demonstrates safe input, and its wording is covered by tests.

## Source

Requested during review of CLI usability and safety ideas.
