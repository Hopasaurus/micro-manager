# T-0202 — mm --help --json: a machine-readable capability list

Today `--help --json` prints the prose help and exits 0, ignoring `--json`
entirely. That contradicts §3.4 ("`--json` … valid with every operation") and
§9.2 ("one JSON object on stdout"), and it leaves capability discovery to
scraping a help page.

## Why it matters

The recommended and optional tiers mean a caller cannot assume an operation
exists. Three ways to find out work today:

- `mm --help --OP` — exit 0 when supported, exit 2 when not. Cheap, no board
  needed, no side effects. The best answer for a shell caller.
- parse the `Operations:` section of `mm --help` — one subprocess for the whole
  list. This is what the pi plugin does (`plugins/pi-mm/src/capabilities.ts`),
  because it gates tool REGISTRATION on the answer and cannot afford one probe
  per operation at session start.
- run it and read exit 2 plus the envelope's `InvalidArgument`. The backstop,
  and what spec-pi-mm-plugin.md §4.3 already renders as "not available in the
  installed mm build".

All three work; none is structured. A tool that wants the surface has to read
prose written for a human, and a help text that grows a section or re-indents a
line silently changes what a machine believes about the build.

## The change

Make `--help --json` emit the envelope, with `result` carrying the operations
and modifiers this build accepts — the same lists `usage.go` already keeps in
step with the parser, so there is no second source of truth to drift.

Not a new `--capabilities` operation: operation and modifier switches share one
namespace (§3.2), and this is not a new capability so much as an existing
output mode finally applying to an existing operation. Not `--version --json`
either: that is about versions.

## Scope

- spec-tools.md §3.4 and §9.2: say what `--help --json` produces.
- The Go CLI: the envelope, and a test that every listed operation is one the
  parser accepts (the existing help/parser cross-check already has both halves).
- plugins/pi-mm: prefer the structured list when the build offers one, and keep
  the `Operations:` parse as the fallback for older builds. `hasOperation`'s
  "unknown means yes" rule stays either way.
- skills/micro-manager-cli/SKILL.md: tell an agent how to ask.
