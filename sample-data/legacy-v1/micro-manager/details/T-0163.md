# T-0163 — gofmt the five drifting files in mm/ and guard against drift

`gofmt -l .` reports five files in the library package. Found while shipping
T-0040 (2026-08-04); the drift predates that change — verified by stashing
the module-path rename and running `gofmt -l` again.

- `mm/init.go` — map alignment in `renderInit`
- `mm/item_test.go` — commented test-table alignment
- `mm/op_fix_test.go` — map alignment
- `mm/palette.go` — const-block alignment
- `mm/validate.go` — comment indentation

All are alignment/indentation-only — zero behavior change — but AGENTS.md's
verification standard is "gofmt; go vet clean" (implementations/golang/
AGENTS.md) and nothing enforces it, so the drift accumulated unnoticed. Any
future edit to these files would reformat them as noise in a diff that should
only contain the edit.

## Do

1. `gofmt -w` on the five files; `gofmt -l .` must then report nothing.
2. Add a guard so the drift cannot come back silently: a Go test that runs
   `gofmt -l` over every package's files and fails naming the dirty ones,
   skipping when gofmt is not on PATH. Mirror the TestClientScripts pattern
   (it shells out to `node` and skips when the tool is absent; assert the
   check actually RAN, not just that it passed). Resolve the module root
   with `go env GOMOD`, enumerate packages with
   `go list -f '{{.Dir}}' ./...`.
3. `go build ./... && go vet ./... && go test ./...` all green; the five
   files must compile and test identically after formatting.

## Out of scope

- No behavior change, no restructuring, no touching files gofmt already
  accepts.
- The repository's pre-existing `gofmt -l` cleanliness is the whole task;
  there is no CI to wire the guard into yet.
