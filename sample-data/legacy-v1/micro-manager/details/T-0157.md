# T-0157 — CLI: stop silently dropping extra positionals for --add/--search

Finding F6 in `project/code-review-007.md`.

`runAdd` and `runSearch` consume `Rest` only when `Subject` is empty (the `--`
fallback). A second positional is silently ignored:

```
$ mm --search alpha extra-word-here    # searches only "alpha"
$ mm --add "Title" more words          # title is "Title"; rest dropped
```

An unquoted multi-word query — a common typo — silently narrows the search
instead of erroring. `--note` and `--block` deliberately consume `Rest`
alongside a non-empty subject, so the surface is inconsistent.

Fix (pick one, be deliberate):

1. Error on surplus positionals: `--add` and `--search` take exactly one
   subject; anything extra is a usage error naming the extra text.
2. Join the surplus into the subject, matching how `--note`/`--block` treat
   `Rest` as the payload.

Option 1 is the safer default: a typo should fail loudly. Whichever is chosen,
the help text for `--add` and `--search` must state the behaviour, and a test
must pin it (extend parse_test.go and/or cli_test.go).

Verify: `go -C implementations/golang test ./internal/cli/`, and both probes
above now behave per the chosen option.
