# T-0026 — Build the test fixture corpus under testdata

## What is there

19 directories under `implementations/golang/testdata/`, loaded by
`mm/fixtures_test.go`:

- **5 clean** — minimal, full (prose, comments, two month groups, an occupied
  slot, unregistered fields, detail files), multi-slot, wide slot width, and
  `clean-ugly` for the legal-but-awkward cases of format spec §10.
- **14 broken**, at least one per invariant, each named for what it breaks and
  asserted to break *only* that. A fixture that trips three rules cannot tell
  you which one a regression touched.

**None is named `micro-manager` or a variant.** If they were, the repository's
own `./check.sh --all` would sweep them up and report the deliberately broken
ones as failures.

## Two findings

**`check.sh` does not apply format spec §4.1 rule 5.** The rule says that for
every key except `title`, a trailing ` #comment` is stripped from the value.
`clean-ugly` sets `project: Clean Ugly — Ünïcode, and a # hash`; this
implementation reads the project as `Clean Ugly — Ünïcode, and a`, and
`check.sh` prints the whole line including the hash. The Go behaviour follows
the spec. It changes no verdict — both agree the directory is valid — so it does
not affect the T-0028 cross-check, but the two disagree on a displayed value and
one of them is wrong.

**An impossible date is reported as a parse-level `format` problem, not as I7.**
`broken-i7-impossible-date` uses `created:2026-02-31`. The value never becomes a
date, so the finding comes from the parser rather than from the invariant pass.
The fixture table records that explicitly rather than pretending otherwise.
