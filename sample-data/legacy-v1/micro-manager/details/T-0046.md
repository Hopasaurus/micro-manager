# T-0046 — Expose a cheap directory fingerprint for change detection

## Context

`spec-tools.md` §2.4 requires a cheap fingerprint of a directory, and
`spec-gui.md` §2.3 makes it the mechanism the browser polls
(`GET /api/v1/projects/:projectId/fingerprint`, default every 5s) and the signal
the SSE broker fans out from. Nothing in the library exposes one today, so the
UI service has no way to notice a change made by the CLI or by a text editor.

## Requirements

1. `Store.Fingerprint() (Fingerprint, error)` derives a value from the **size and
   modification time** of the files the directory owns — `backlog.md`, every
   `working.NN.md`, `done.md`, and every `details/*.md` — plus the directory
   listing itself, so a new or deleted slot file changes it.
2. It MUST NOT read or parse file bodies. `stat` only. This is polled once a
   second per open tab in the worst case.
3. `theme.json` and `config.json` are **not** part of it: they are outside the
   format spec (`spec-gui.md` §8.2) and a theme edit must not look like a data
   change. If the UI needs to notice a theme edit it gets its own signal.
4. The value is opaque to callers, comparable for equality, and printable for
   logging and for the JSON payload. A hex digest of a canonical
   `name\0size\0mtimeNanos\n` listing is the obvious shape.
5. Equality means "no need to re-read" and nothing stronger. Staleness is caught
   at write time by size-and-mtime (`spec-tools.md` §7 rule 5), never by polling
   — the doc comment must say so, because the next reader will be tempted to use
   this as a lock.
6. An unreadable directory returns an error; a missing optional file is simply
   absent from the listing, not an error.

## As built

`mm/fingerprint.go`. `Store.Fingerprint() (Fingerprint, error)` returns a
64-character hex sha256 over `name\0size\0mtimeNanos\n` per owned file, sorted by
name. `Fingerprint` is a string type: comparable, printable, opaque.

Three decisions worth keeping:

- **NUL as the separator**, because it is the one byte a filename cannot
  contain. With any printable separator two different listings could render to
  the same bytes and therefore to the same digest.
- **Owned files are the format spec's files**: `backlog.md`, `done.md`, any
  `done-YYYY.md` archive, every `working.NN.md` (and a bare `working.md`, which
  is still data even though I10 reports the name), and every non-template file
  in `details/`. `theme.json`, `config.json`, `structure.md` and editor debris
  are excluded, and a test asserts each of them fails to move the value.
- **A file that vanishes between the listing and the stat is skipped**, not an
  error. The next poll sees a directory without it, which is exactly what the
  caller needed to learn.

Per-file stamps are deliberately not exposed. The internal `stamp` type holds
them and a `Fingerprint` carrying them would let a UI re-read one file rather
than the directory, but no spec asks for it and the extra surface would invite
using this as a lock, which §2.4 rule 4 forbids.

`copyFixture` was added to `fixtures_test.go` for this item: the corpus under
`testdata/` is read-only by convention, and these tests must write. Note that
two copies of one fixture legitimately fingerprint differently — mtime is part
of the input — so every baseline is taken from the copy under test.
