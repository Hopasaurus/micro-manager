# T-0042 — Implement status, next and search in the library

## Context

`spec-tools.md` §5.2 recommends `--status`, `--next` and `--search`. They sat in
`## Someday` while every required operation shipped, which was the wrong order:
`spec-gui.md` §6.1 maps three UI surfaces onto them — `app-status`, the top card
of `board-column-ready`, and `search-input` — so the GUI cannot be built without
them.

`--find` was in this item's original title and is already implemented; the title
was corrected when the item was promoted.

## As built

`mm/status.go` and `mm/search.go`. Library only — the CLI switches are
**T-0071**, and nothing here depends on them.

**`Status` is one read.** Counts by section, done, the directory summary with
its slots, plus `Next` and `OldestReady`. A status screen that needed three
calls would show three moments in time, which for a directory the CLI and a text
editor are also writing is a real inconsistency rather than a theoretical one.

**"Oldest untouched" means never started.** An item that was started and paused
has been looked at; the one that has sat since it was written has not, and that
is the one worth surfacing. An item with no `created:` cannot be compared, so it
only wins when nothing else qualifies — it is aging too, just unmeasurably. When
every Ready item has been started, the top of the list stands in.

**`Next` returns `ErrNotFound` on an empty section**, which is what lets the CLI
exit non-zero and a script stop rather than start something arbitrary.

**Search decisions**, all of which the GUI and the CLI must share or they will
find different things in different windows:

- A plain query is a **case-insensitive substring**, because that is what a
  person typing into a box expects. A regex is matched **exactly as written**, so
  case-insensitivity there is the caller's to ask for with `(?i)`.
- **One hit per matching location**: title, the tag list as a whole (not one per
  tag), and one per matching line of the detail body. A detail hit carries the
  detail file and line number, which is what makes it navigable.
- Order is item order, then title, tags, detail within an item. A result list
  that reordered itself between identical queries would be unusable as a way to
  find the same thing twice.
- `State` defaults to everywhere. The reason to search is usually that you
  cannot remember where something is.
- A `detail:` pointing at a missing file is I8's business; search skips it and
  keeps going. Refusing to search a broken directory removes the tool exactly
  when it is needed.
- `SearchItems` reduces hits to distinct items for the board's `?q=` filter,
  which renders cards and would otherwise draw one card per matching line.
