# T-0043 — Implement archive for rolling months into done-YYYY.md

## Context

`spec-tools.md` §5.3: `--archive [--before YYYY-MM]` moves old month groups from
`done.md` to `done-YYYY.md`, and **MUST warn that archived items leave the ID
pool and stop being covered by I1/I2** (`spec-file-format.md` §10.5).
`spec-file-format.md` §5.3 is the other half: "when the file grows unwieldy,
trailing years MAY be moved to `done-YYYY.md`… those files are outside this
specification and are not validated."

`done.md` is the one file items are never removed from. This repository's own
board is already 87 closed items in a single month group.

## As built

`mm/op_archive.go` — `Store.Archive(ArchiveRequest, today) (ArchiveResult,
TxResult, error)`, plus `ReportOptions.IncludeArchives` in `mm/report.go` for
reading archives back.

- **Cutoff is month-granular.** `ArchiveRequest.Before` is a `Date` whose day is
  ignored: the switch is `--before YYYY-MM` and a month group is the finest
  grain `done.md` records, so a full date rounds down to its month rather than
  being refused. A month outside 1–12 is `ErrInvalidArgument`. The zero value
  means the month of `today`, so a bare archive keeps the month the board is
  living in and rolls everything before it. `ArchiveResult.Cutoff` reports what
  was applied, because it can come from that default.
- **Whole groups move, heading included.** An empty group is dropped (nothing to
  archive, and no archive file is created for it). A heading that is not
  `YYYY-MM` is left exactly where it is: it names no year to file under and is
  already a violation — repairing it is `Fix`'s job.
- **Archive first, `done.md` second** (§7 rule 4). An interruption between the
  two writes leaves the group in both files rather than in neither, and
  insertion skips an ID the archive already holds, so re-running completes the
  interrupted move instead of writing a second copy. `TestArchiveHealsAn`
  `InterruptedRun` is that case, staged by hand.
- **The archive is seeded and then treated like any other done file.** A fresh
  `done-YYYY.md` is rendered with `done.md`'s shape, parsed back with
  `parseDoneG`, and filled through `doneFile.InsertItem` — so one insertion path
  serves both a new archive and a merge into an existing one, and month groups
  land in descending order either way. Items are replayed BACKWARDS because
  `InsertItem` always inserts at the top of a group.
- **Archives are never validated.** `load()` does not read them, `tx.reparse()`
  does not see them, and the parse findings from an archive are discarded on
  purpose: `--check` will never look at these files (§10.5), and reporting
  findings from them would give the format a rule it does not have. They are
  read with a stamp taken before the read, so the §7 rule 5
  concurrent-modification check still covers them.

## The thing the spec does not say: detail files

Archiving an item whose `detail:` file exists makes that file an **I9 orphan** —
nothing in `backlog.md`, a working file or `done.md` references it any more.
§10.5 names only I1 and I2 as the coverage archiving costs; it does not mention
I8/I9, and this is not a small effect: on this board, archiving `2026-07` moves
87 items and strands **51** detail files, taking the directory from clean to 51
findings.

Four ways out were considered:

1. **Orphan and report** — what was built.
2. Move the files to a parallel `details-YYYY/` and rewrite the archived
   `detail:` field. Keeps the board clean, but invents on-disk layout the format
   spec does not define, and hand-restoring an archived line then silently
   breaks I8 until the file is moved back too.
3. Teach I9 that an archived item still claims its detail file. That is a change
   to the invariant, so it needs `spec-file-format.md` and `check.sh` to change
   together — the two validators agreeing is the property this repository
   protects hardest.
4. Delete the files. Destroys the long-form record §5.4 says is never deleted on
   completion.

(1) wins on the spec's own precedent: §5.1.6 says of the identical situation in
`--remove` that an implementation "MUST either delete it in the same transaction
or report the orphan; silently leaving an invalid directory is not conforming."
Deleting is out by §5.4, so reporting is what is left. It is also the only
option that is reversible by hand — pasting a group back into `done.md` makes
the board clean again with no file to move — which is the property the whole
format exists to keep.

So the finding is made DELIBERATE rather than accidental: each orphan's I9 key
is added to the transaction baseline (the mechanism `op_remove.go` already uses,
or the pre-commit check would refuse the write), returned in
`ArchiveResult.DetailOrphans`, and named in a warning. **T-0166 carries the spec
question**; nothing here decides it.

## Splice care

Two line-level traps, both covered by tests:

- A month group's range must NOT include the final empty element `splitLines`
  gives a file that ends in a newline — that element IS the newline, and taking
  it strips the file's last line ending. `groupEnd` stops one short of it.
- Removing a group leaves the blank line that separated it from the group above.
  That is right in the middle of the file and untidy at the end of it, so
  `dropTrailingBlank` collapses it, the way `fileEdit.RemoveItem` does for one
  line. `TestArchiveLeavesDoneTidyWhenEverythingGoes` pins the exact bytes of a
  `done.md` that has lost every group: frontmatter and prose intact, one
  trailing newline, and still writable by the next `--finish`.

## Reading archives back

`ReportOptions.IncludeArchives` (spec-tools.md §5.1.11) reads every
`done-YYYY.md`, newest year first, and the "this period has been archived"
warning goes quiet only when an archive was actually read — with the option set
and no archive on disk, nothing was hidden and the warning is still the truth.
This retires the `--include-archives is not implemented yet (T-0043)` stub in
`internal/cli/run.go`.

## Not done

The CLI has no `--archive` switch: no optional operation from §5.3
(`--archive`, `--migrate`, `--stats`, `--export`, `--top-up`) is wired, and
wiring one is front-end work rather than library work. **T-0167.**
