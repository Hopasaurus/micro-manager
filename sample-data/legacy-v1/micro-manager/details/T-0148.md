# T-0148 — Check if flicker fixes need to be applied to more paths

The /new and /item paths still flicker, check if the fix was applied here and if not create tasks to apply.  Also check if there are other paths that may need fixes and make tasks for those paths.

T-0150 might fix this.

## Findings (spike done, 2026-08-04)

Investigated in the code and in headless Chromium (playwright-core, chromium
151) against the running service and the clean-full fixture.

**1. T-0150 IS applied on /new and /item.** The board on those pages carries
the same refresh wiring as /board (`hx-get …/board?fragment=1`,
`hx-ext="morph"`, `hx-trigger="sse:board from:body"`, `hx-swap="morph"`), so
every htmx-triggered render sends `X-Someday-Collapsed` and is born collapsed.
Direct loads (the + link, a reload, a bookmark) get no header and rely on the
DOMContentLoaded fixup — and that fixup beats first paint: measured collapse
at 31–52 ms vs first-paint at 44–56 ms on /board, /new and /item, so the
someday column never paints expanded on any of the three. The someday
hypothesis for the report is disproven.

**2. The /new and /item flicker is the mutation swap.** Every save from the
panel swaps the ENTIRE board outerHTML (item-panel.html:34/109/122 — the edit
form, the action buttons, the note form): a full teardown-and-rebuild of
every column and card (31,825 bytes in clean-full; the report's flicker
source 2) on the page whose main interaction is the panel save. T-0138 made
these swaps outerHTML for exactly one reason — a morph swap from outside the
board re-registered the `every 30s` poll and leaked a chain per mutation —
and T-0139 removed every `every` clause (grep: none remain in templates/ or
static/). Verified with the item form flipped to morph: the save lands, the
panel dismisses, the board element is preserved, and ZERO board/status
fetches follow in 12 s with the stream up — no chain returns. The T-0138
rationale is dead; the swaps can morph again. → [[T-0161]].

**3. Other paths.** The + link (partials/board.html:44) is the only board
path that still full-page-loads: the card title links carry href + hx-get
progressive enhancement, the column add links are plain anchors. → [[T-0162]].
The theme shell swap is already tracked ([[T-0136]]). The app-status OOB
swap is outerHTML on every mutation but is a one-line footer (negligible;
noted in T-0161). check.html:23, projects.html:22 and project-card.html:33
swap outerHTML only on explicit user actions — fine. The report view has no
refresh triggers — fine.
