# T-0151 — Delay in shutdown

Shutdown takes several seconds and logs this error:

{"time":"2026-08-03T09:31:17.250799-04:00","level":"ERROR","msg":"failed to shut down server within given timeout","error":"context deadline exceeded"}

## Cause

An open SSE event stream (`GET /api/v1/events`) kept the connection active
through the whole 5s `GracefulTimeout`. echo's `StartConfig` graceful shutdown
runs `http.Server.Shutdown` with that timeout, and `Shutdown` waits for active
connections to go idle. The stream handler only watched its request context
and the subscriber channel, neither of which fired on shutdown, so the
connection never went idle, the timeout expired, and the error above was
logged. Reproduced: shutdown took 5046ms with a stream open.

## Fix

- `Server` gains a `shutdown` channel, closed by a goroutine in `Start` when
  Start's context is cancelled (`sync.Once` so a second Start cannot
  double-close it).
- The events handler selects on `Service.Done()` (the API layer's view of the
  channel) and returns, so the connection goes idle within milliseconds of
  the stop signal.
- Regression test `TestShutdownClosesEventStreams`: with a stream open,
  cancellation must return Start well before the 5s window, and the stream
  itself must close. Fails without the handler case (held open past 2s).

Shutdown with a stream open now takes ~60ms and logs nothing.
