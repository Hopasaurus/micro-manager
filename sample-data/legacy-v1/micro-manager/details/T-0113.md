# T-0113 — Spec: parameterize the ID token (prefix + width) in spec-file-format.md

First task of the T-0112 spike. **The format spec is normative: nothing below
can land until this task defines the grammar.**

## What the format says today

- §3.3: `ID = T-` followed by exactly four ASCII digits; `T-42` is invalid.
- §3.3: "The four-digit width caps a directory at 9999 items; a future spec
  version may widen it, so readers SHOULD match `T-` followed by digits and
  treat a width other than four as a version mismatch rather than crashing."
- §3.1: the reference implementation slices a fixed item-line prefix and is
  safe only because that prefix is pure ASCII by construction.
- `next_id` (backlog.md frontmatter) is a single counter for the whole
  directory.

## The spike's request (T-0112)

- Choose the task prefix per board (the directory).
- Choose the ID digit width; 3–6 digits recommended, a soft suggestion (a
  warning, not a hard stop) outside that range.
- "Or even on a per task basis" — mixed prefixes within one directory — is
  recorded as a possible later phase, gated on this task's decision.

## Decisions this task must make and write into the spec

1. **Declaration site.** `id_prefix` (default `T`) and `id_width` (default 4)
   in backlog.md frontmatter next to `next_id` — the directory declares its own
   grammar once, every reader reads it. Absent fields = today's behavior,
   byte-identical.
2. **Prefix charset.** Keep it tight: one ASCII letter (`[A-Z]`, or allow
   lowercase? decide), because the ID appears in the fixed item-line prefix
   that reference parsers slice by byte offset (§3.1/§4.2) and in filenames
   (`details/<ID>.md`, `working.NN.md` width is a SEPARATE knob — §3.3 `SLOT`
   already parameterizes slot width; do not conflate them).
3. **Width rule.** Accept 3–6 with a warning beyond (not an error), and a
   reader that cannot honor the declared grammar MUST refuse loudly, never
   silently misparse. The 9999-item cap note generalizes to `10^WIDTH - 1`.
4. **I2 stays per-directory.** `next_id` remains one monotonic counter per
   directory; mixed prefixes (per-task) are out of scope here and tracked in
   T-0118.
5. **Migration.** Existing directories declare nothing and keep `T` + 4;
   renumbering an existing directory is NOT a goal (I2 forbids it) — the knob
   is for new directories and new `--init`s.

## Referenced by

T-0114 (library), T-0115 (CLI), T-0116 (check.sh), T-0117 (GUI), T-0118
(per-task phase). `spec-tools.md` §5.1.x and `spec-gui.md` §4 repeat the ID
form in examples; they must be reconciled with the new token, not left
contradicting it.

## Update (post-ship)

`id_prefix` may now be **one to four ASCII letters, all uppercase** (`MM`,
`FOO`); lowercase and mixed case are invalid, matching is exact. Default
remains `T`. Touched: §3.3.2 table + rules 2/3, §5.1 table + paragraph,
Appendix A `P`-substitution note.
