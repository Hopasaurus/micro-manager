# T-0103 — Error when clicking "Save and add another": render board: html/template:board.html:35:77: no such template "item-panel"

## Notes

**2026-07-31** — Already resolved in the working tree before I started: item-panel had been extracted from item.html into partials/item-panel.html, which puts it in every page set. Confirmed by restoring HEAD's item.html and deleting the partial - TestShippedTemplatesParse then fails with the reported error. So the work here is the guard, not the symptom: verifyReferences walks each set's parse trees for template/block nodes and refuses a reference the set does not define, turning this class of bug into a startup failure. That is what render.go already claimed to do ('a broken template is a startup failure'); Go resolves {{template}} at execution, so parsing alone never checked it.

Guard added plus two tests (cross-page reference refused, partials still shared). Verified live: Save and add another added T-0020, refreshed the board and re-opened a fresh form, no error, clean console.
