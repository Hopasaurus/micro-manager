# T-0153 — CLI: --help/--version must not vanish under --json/--porcelain (empty stdout, exit 0)

Finding F1 in `project/code-review-007.md`.

`Run` (internal/cli/cli.go:110-118) handles `--help` and `--version` with a
direct `return ExitOK` that bypasses `finish`. When a machine mode is on, `Run`
has already replaced `env.Stdout` with `io.Discard`, so the text is lost AND no
JSON envelope is emitted:

```
$ mm --version --json    # stdout empty, exit 0
$ mm --help --porcelain  # 0 bytes, exit 0
```

A script parsing stdout gets nothing — indistinguishable from a crash except
for the 0 exit code. Violates §9.2 ("the envelope MUST be present in both
cases").

Fix options, either acceptable:

1. Route `--help`/`--version` through `finish` so the envelope carries the
   version (or help text) in `result`.
2. Treat them as meta-switches that always print to the real stdout regardless
   of machine mode (§3.4 lists them as global switches, not operations).

The fix MUST include a regression test combining `--help` and `--version`
with both `--json` and `--porcelain`, asserting non-empty stdout. The fix and
test are the same change; do not split them.

Verify: `go -C implementations/golang test ./internal/cli/`, plus the manual
probes above against the built binary.
