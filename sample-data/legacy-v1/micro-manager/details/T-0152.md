# T-0152 — Should be able to drop on "SOMEDAY" even when collapsed

When collapsed the dropped item should go to the bottom of the list.

## Resolution (2026-08-04)

mm.css hides a collapsed column's body outright (`display: none`), so
`closest('.mm-column__body')` — how mm.js resolved every drop — found nothing
and the drop was silently discarded. The same failure as T-0100 from a
different cause: there the body was too short, here it is not in the layout at
all. Confirmed in a browser: `elementFromPoint` over a collapsed Someday
returns `board-column-someday-header`, whose `closest('.mm-column__body')` is
null.

- `bodyAt()` in mm.js resolves a hit anywhere inside
  `.mm-column[data-collapsed="true"]` to that column's hidden body; the
  dragover and drop handlers use it. Only the lookup changed — the body is
  still the element §7 works in terms of, since it carries `data-column`.
- `hoverTarget()` forces the index to the bottom when the target is collapsed,
  and skips positioning the placeholder: inside a hidden body every rect is
  zero. The column's own `data-drop-target` border is the feedback.
- Covers the keyboard path too (§7.4), because both go through `hoverTarget`.

Verified end to end in a real browser against a throwaway copy of sample1: the
drop moved the item to the bottom of Someday and `check.sh` stayed clean.
Three cases in `jstest/mm.test.js` (pointer, keyboard, and an expanded-column
guard so the rule does not leak), plus `TestCollapsedColumnsResolveADrop` as
the source-shape guard for where node or jsdom is absent. spec-gui.md §7.1
now states the rule.
