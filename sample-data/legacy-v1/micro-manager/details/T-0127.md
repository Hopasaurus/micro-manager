# T-0127 — GUI: render `refs` links

GUI task following the T-0104 spike (plan-board-links.md). **Gated on
T-0125/T-0126**: the spec defines the form, the validators pin the shape; the
GUI renders. No CLI change at all — `mm --edit --set refs:py:T-0012` and
`--unset refs` already reach unknown keys (op_update.go, usage OpEdit).

## Why

A `refs:` value is data on an item line; its purpose is to be *seen and
followed*. The GUI is the only component with a tree-wide view (discovery,
favorites, recent), which is why decision 4 of plan-board-links.md gives
resolution to the GUI and to nobody else — and why the missing/ambiguous
rendering must follow the §10 rule 5 policy (a favorite on an unmounted drive
is not a deleted project).

## What to build

- **Directory summary carries `board`**: the `/api/v1/projects/:projectId`
  summary (and `Directory` in the Go library) gains the declared slug, "" when
  absent. This is the lookup key: the GUI resolves a slug by scanning the
  directories it knows for a matching `board`.
- **Item rendering**: a `refs:` value on an item line renders each element as
  a link in the item panel (and on the card's detail surface), addressed by
  the target board's projectId and the target item's ID — routes keep
  projectId, links use the slug (decision 7). Nothing reconstructs a path from
  a slug; resolution is a lookup among known directories, exactly as projectId
  is resolved today.
- **Three resolutions, three renderings**: slug resolves → clickable link
  (`data-testid` includes the target board and item); slug resolves to
  nothing → the §10 rule 5 missing treatment (`data-missing="true"`), the
  element rendered as text, never a dead link; slug matches two known boards →
  rendered as ambiguous, both boards named, no guess (the `mm fix` tie
  discipline). A ref pointing at a renumbered item (mm fix in the target
  board, decision 6) renders as missing — the owned, documented cost.

## Verify

A harness board carries `board: py`; a second board carries an item with
`refs:py:T-0012`. Tests assert: the link renders clickable and resolves to the
target board's URI; removing the target board from the known set renders
`data-missing`; two boards declaring `board: py` render ambiguous with both
named. The web test suite and `go test ./...` stay green.

## Update (post-ship)

Shipped 2026-08-02 (commit pending).

- **Library**: `mm.Directory` gains `Board`, populated from `backlog.md`
  frontmatter in `dirModel.directory()` — the lookup key the GUI resolves
  against. Discovery carries it automatically (its results are `Directory`
  values), so the registry's known set is the whole resolution space.
- **API**: `jsonDirectory` gains `board,omitempty`; `jsonItem` gains
  `refs,omitempty` as formatted `slug:ID` strings. The API carries the DATA;
  resolution stays with whichever client holds the tree-wide view.
- **Resolution** (`internal/web/refs.go`): `refResolver` built once per
  render from the registry's known set (snapshot under read lock). Three
  outcomes per element: exactly one known board + item present → resolved;
  no known board, or the item not in the resolved board (the mm-fix renumber
  cost, checked via `store.Get` with a per-render memo) → missing; several
  boards → ambiguous with all names. Never a path reconstructed from a slug.
- **Rendering**: the card renders a compact refs list after tags; the panel
  renders a References section whose ambiguous case spells out the boards.
  Testids carry the `x-` prefix §5.1 requires for additions to the closed
  required list (`x-item-<id>-ref-<slug>-<target>`, `x-item-<id>-refs`,
  `x-item-refs`, `x-item-ref-<slug>-<target>`). State rides `data-missing`/
  `data-ambiguous`, matching the §10 rule 5 vocabulary. CSS: ref pills on
  the card, list rows in the panel, muted+struck for missing, blocked colour
  for ambiguous.
- **Tests** (`internal/web/refs_test.go`, 5): a `writeRefsBoard` helper
  writes minimal boards inline (the shared corpus has no pair whose slugs
  and items line up). Resolved: card + panel link to
  `/p/<targetProjectId>/item/<id>` with the element as text. Unknown board:
  `data-missing`, text, never an anchor. Renumbered item: `data-missing`
  even though the slug resolves. Ambiguous: `data-ambiguous`, both boards
  named in the panel, no guess. API: summary carries `board`, items carry
  `refs`. Plus `TestDirectoryCarriesBoard` in mm (declared slug and absent
  → "").
- **Smoke with the real binary**: two boards (`board: py` / `board: go`),
  `mm-ui` resolves `refs:py:T-0001` on the go board to
  `/p/a154dbbba9f5/item/T-0001` (the py board's projectId); serving only the
  go board renders the same ref `data-missing="true"`. Both boards pass
  `check.sh`.
