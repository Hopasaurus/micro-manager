# T-0182 — /mm command surface

From [[project/spec-pi-mm-plugin.md]]. Spec §5: one command 'mm' with ops as args, mirroring the tools and sharing argv builders and formatters. Includes /mm find (list located boards, in-use marked), /mm init (create + pin a board; --prefix/--description validated before invocation), /mm board no-PATH (identity + description + status summary), and /mm describe TEXT (fails rather than touching structure.md when mm lacks the op). Interactive confirmations via ctx.ui.confirm when hasUI. Prints the same results the tools return; stops with the resolution failure when no board is found.

## As built

`plugins/pi-mm/src/command.ts`. The spec says the command shares the tools'
"argv builders and formatters"; this shares **the tools themselves**. A typed
line is parsed into the parameters a tool takes, and then that tool is called.

That is what makes §5's rules true by construction rather than by discipline:

- *"MUST print the same formatted results the tools return"* — it prints the
  tool's result, so there is no second renderer to drift. A contract test runs
  `/mm status` and `mm_status` against one real board and compares the bytes.
- *"MUST resolve the board exactly like the tools"* and *"MUST NOT run when no
  board is found"* — the command resolves nothing; the tool does, and the
  command prints its refusal.
- *"`/mm remove` confirms the same way"* — the same guard runs, from the same
  code, with the command's own `ctx` handed through, so the dialog the user
  sees is the tool's.

**A typed `/mm remove T-0042` asserts `confirmed: true`.** A human typing the
command IS the user asking, which is exactly what that parameter means when a
model sets it — and the interactive prompt still runs, so a typed removal is
confirmed twice, like a tool call from the agent.

**The tokenizer keeps a quoted title one argument**, for the reason
`spec-tools.md` §5.1.2 gives: an unquoted multi-word title silently becoming
several arguments is the mistake worth preventing. `/mm note ID TEXT` and
`/mm describe TEXT` take the rest of the line unquoted, because a human typing
a sentence should not have to think about quoting it.

**An unknown op prints help.** `/mm stat` is a typo, and running `--status` for
it would be the plugin deciding what someone meant.

## Not built, and said so

`/mm tick` and `/mm archive` are in §5's list, but their tools are the
recommended set (**T-0184**) and do not exist. They answer "not available yet"
and name the CLI, rather than half-running an operation the plugin has not
wired.

## `/mm context [on|off]`

§5 puts this in the command surface and §6 says the setting is *session state,
not configuration*. `src/settings.ts` holds it and resets at `session_start`, so
a toggle cannot survive into the next session and become configuration wearing a
command's clothes. The injector that reads it is **T-0183**; §9's `context` key
will seed the default rather than replace the toggle.

## Verification

`src/command.test.ts` covers the only genuinely new part — the mapping from a
typed line to a tool call — plus the three §5 rules that would be easy to break:
the printed text is the tool's, a tool error stays an error, and the `ctx`
reaches the tool rather than being re-created. `src/mm-contract.test.ts` runs
`/mm` against a real board, compares `/mm status` with `mm_status` byte for
byte, and drives a declined `/mm remove` to prove the confirmation is the tool's
and the item survives.

116 tests: all pass with `mm` on PATH, 110 pass and 6 skip without.
`tsc --noEmit` clean, and `pi --list-models -e ./src/index.ts` still loads the
extension through pi's own loader with the command registered.
