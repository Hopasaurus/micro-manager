# T-0005 — Parse item lines, preserving unregistered fields verbatim

## Context

Format spec §4.2. The prefix `- [_] [T-NNNN] ` is fixed-width and pure ASCII, so
byte offsets are safe: box at 4, ID at 8..13, title from 16.

## Requirements

- Recognise with `^- \[[ x]\] \[T-[0-9]{4}\] .` — the trailing `.` requires a
  non-empty title.
- Split the remainder on the three-character sequence `" | "`. First part is the
  title; each other part is a field split at its **first** `:`.
- A field part with no `:` is an error. A repeated key is an error. A value
  containing `|` is an error.
- Unknown keys go into `Extra` and are never rejected.
- Only `backlog.md` and `done.md` contain item lines. A `- [ ]` line in a
  working file is a subtask and must not be parsed as an item — getting this
  wrong produces phantom items with no IDs.

## Known traps

Format spec §10.2: a title containing `|` followed later by `:` — `Fix a | b: c`
— parses as a truncated title plus a well-formed unregistered field `b:c`, and
is accepted silently. Do not "fix" this in the parser; the spec documents it as
a limitation and the writer is what prevents it. Reject `|` in titles on write.
