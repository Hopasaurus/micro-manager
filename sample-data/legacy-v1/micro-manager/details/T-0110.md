# T-0110 — Drag-and-drop doesn't seem to work for reordering tasks in Ready.

## Notes

**2026-08-01** — Root cause is a feedback loop in mm.js's dragover handler. hoverTarget inserts the drop placeholder BETWEEN cards, so every card below it sits one placeholder-height lower. The next dragover measured getBoundingClientRect with that placeholder still in the DOM, so the pointer could never reach the shifted midpoints - the computed index stayed pinned wherever it first landed and the placeholder never moved again. Dragging DOWN therefore produced a drop index equal to the card's own position: a no-op that reads as 'drag and drop is broken'. Dragging UP was unaffected, since the cards above the placeholder are the ones it does not displace. Fix is one line: clear placeholders before measuring.

Proved in a real browser by instrumenting data-drop-index across a simulated continuous drag: pinned at 0 through y=260 (past the midpoint at 241) before, advancing 0-1-2-3-4 after. One-slot and multi-slot downward drags now land exactly where aimed, on screen and on disk. Source-shape guard added in dragdrop_test.go asserting the clear happens before the measure; verified it fails without it.
