# T-0095 — importTheme must not write an envelope missing the theme key over a user's theme.json (F3: data loss)

Finding **F3** of `project/code-review-006.md` (CONFIRMED). Data loss.

## The bug

`internal/web/api/files.go:455` — the bare-document fallback:

```go
if req.Theme == nil {
    var doc rawDocument
    if json.Unmarshal(body, &doc) == nil && len(doc) > 0 && doc["theme"] == nil {
        req.Theme = doc          // ← the envelope itself
    }
}
if req.Theme == nil {            // ← can now never fire
    return fmt.Errorf("%w: a theme document is required", mm.ErrInvalidArgument)
}
```

The fallback exists to forgive a client that PUTs the theme as the whole body.
It also swallows the **wrapped envelope** when the `theme` key is missing.

`POST /api/v1/themes/import` with body `{"destination":"system"}` — a client
that simply forgot the `theme` key — assigns `req.Theme = {"destination":"system"}`.
Probed against `mm`: it parses, validates clean, and `t.Save` writes
`{"destination":"system"}` **over the user's system `theme.json`**. Destination
`project` clobbers a project's theme the same way. Only `library` is safe,
because the empty `t.ID` is rejected first.

## Fix direction

The fallback must require that the document actually look like a theme — at
minimum, that it carries no `destination`/`dryRun` keys (the envelope's own
keys). If the document is the envelope without a `theme` member, fall through
to the real "a theme document is required" error.

## Verify

- `POST /api/v1/themes/import` with `{"destination":"system"}` must 400 and
  must not touch the on-disk theme file.
- The bare-theme-document form (whole body is the theme) must still import.
- A regression test against the system theme file's bytes after the call.

## Notes

**2026-07-31** — Deviation worth recording: satisfying the detail file's 'bare-theme-document form must still import' required more than the guard. Import mandates a destination and had no source for it outside the envelope, so the bare form could only ever 400. Per spec-gui.md 8.8 ('import accepts that file', destination 'an explicit parameter with no default') the query string is now the fallback for destination, projectId and overwrite; the body wins where it said anything. Posting an exported .mm-theme.json verbatim to ?destination=library is now a complete request.

Two tests added: envelope-without-theme is refused and the on-disk theme is byte-identical afterwards; bare document imports via ?destination=. Verified the first fails (200, want 400) against the old fallback.
