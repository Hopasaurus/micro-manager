# T-0016 — Implement detail files and title synchronisation on rename

## Context

A detail file duplicates its item's `id` and `title` in frontmatter. That
duplication exists solely so drift is detectable (I9), which means every code
path that changes a title has to maintain it.

## Requirements

- Create from `details/_template.md`, filling `id` and `title` to match the item
  line, and set the item's `detail:` field to `details/<ID>.md`.
- **Changing an item's title must update the detail file's frontmatter `title`
  in the same transaction.** This is the sharpest coupling in the operation set
  and the easiest to miss, because the item write succeeds on its own.
- The path must always be `details/<that item's ID>.md`. Reject anything else.
- Detail files never move. The item line travels between backlog, working slots
  and done; the file stays put and `done.md` keeps the `detail:` field.
- Files beginning with `_` are templates: exempt from I9, never treated as an
  item's detail.
- On remove, either delete the detail file in the same transaction or report the
  orphan. Silently leaving an invalid directory is not acceptable.
