# T-0167 — CLI: wire the optional operations from spec-tools.md §5.3, starting with --archive [--before YYYY-MM]

## As built

`mm --archive [--before YYYY-MM | --age DAYS]`, the first §5.3 operation to
reach the CLI. `--dry-run`, `--json`, `--porcelain` and `--quiet` all work on it
like every other operation.

- **Two spellings, one cutoff.** `--before YYYY-MM` is the explicit month;
  `--age DAYS` is the policy form §5.3.1 defines ("archive a month 15 days after
  it ends"). Giving both is a usage error rather than a precedence rule to
  remember. A full date is accepted for `--before` and its day ignored, because
  a month group is the finest grain `done.md` records.
- **`--age` resolves through `mm.ArchiveCutoff(today, days)`, in the library.**
  It is a rule, not a translation: a UI that grows a scheduled archive has to
  reach the same cutoff from the same policy, and two implementations of "which
  months are old enough" would eventually disagree by a day. The condition is
  monotone in the month — an older group's last day is earlier — so it collapses
  to the one exclusive month `Archive` already takes.
- **The warnings survive `--quiet`.** §5.3 makes the ID-pool warning mandatory,
  and this is the operation that takes data out of the checked set; quiet asks
  for less commentary, not for less of the one thing the spec insists is said
  out loud. They go to stderr, so `--porcelain` stays a clean record stream.
- **Porcelain is one record per moved item, `id file`**, built from the
  transaction's change set rather than from a filename this layer would have to
  construct: the library already knows which archive each item landed in.
- **The cutoff is always reported**, because it can come from a default or from
  `--age` — an operation whose boundary is invisible is one the caller cannot
  check.

## The honest caveat

The library still strands detail files (T-0043's option 1), which
`spec-file-format.md` §5.6 now forbids — **T-0168** is the fix. Wiring the
switch does not make that worse, but it does put it in front of users, so the
`--help --archive` page says so in as many words, and the run names every file
it stranded. On this board a dry run is 87 items and 51 stranded detail files,
which is exactly the number T-0043 predicted:

```
$ mm --dir implementations/golang/micro-manager --archive --dry-run
would: archived 87 item(s) from 1 month(s) before 2026-08
  2026-07
  wrote done-2026.md
mm: warning: 87 archived items left the ID pool: …
mm: warning: 51 detail files are no longer referenced by any item …
```

When T-0168 lands, three things change together: the warning, the
`--help --archive` text, and the sentence in `project/SKILL.md`.

## The other four

`--migrate`, `--stats`, `--export` and `--top-up` are NOT wired, because there
is nothing to wire them to: no library operation exists for any of them.
`--migrate` is **T-0044** and `--stats` is **T-0045**; `--export` and `--top-up`
have no item yet. Each is a handful of lines here once its library operation
exists — a `runX`, a render, a JSON shape, a porcelain column list and a help
page — so the wiring belongs with the operation rather than in a second CLI
task.

## Tests

`internal/cli/archive_test.go`: the roll-out end to end (dry run writes nothing,
the real run splits by year, the directory still validates, a second run is a
no-op), the mandatory warning under `--quiet`, `--age` and `--before` agreeing
on one cutoff with the boundary day proven either side, the default cutoff, JSON
and porcelain, the stranded-detail warning followed by the I9 finding it
predicts, and five bad cutoffs.

`mm/op_archive_test.go`: `TestArchiveCutoffFromAge` (seven boundary cases —
mid-month, the last day of a month, exactly old enough, one day short, the year
end, and February 29th) and `TestArchiveByAgeMovesTheRightGroups`, which checks
the cutoff actually selects the groups the policy names.
