# T-0155 — CLI: JSON error envelope must record an id only when the subject is one

Finding F3 in `project/code-review-007.md`.

`dispatch` (internal/cli/run.go:53) records `env.json.subject` from any
operation's subject that happens to parse as an ID:

```go
if id, err := parseIDIn(in.Subject, g); err == nil {
    env.json.subject = string(id)
}
```

The comment says "where applicable" but applicability is never checked. On
failure the envelope's `errors[].id` is then misleading:

```
$ mm --wip 100 --json    # fails: 100 slots need 3 digits, width is 2
"id": "T-0100"           # --wip is about slot files, not item T-0100
```

Same shape for `--add 7` or `--search 42` on failure.

Fix: gate the recording on the operations whose subject IS an item id —
`show edit remove move start pause finish block unblock note` (the same set
`subjectID` already gates on). For every other operation leave the subject
unset.

Verify: `mm --wip 100 --json` in a 2-width directory must NOT carry an `id`;
a failing `mm --show T-9999 --json` must still carry `id: "T-9999"`.
`go -C implementations/golang test ./internal/cli/`.
