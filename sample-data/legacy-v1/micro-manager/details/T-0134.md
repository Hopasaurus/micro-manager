# T-0134 — Per-column fragment routes and hx-triggers (gated on T-0131)

## Context

`research-app-fllicker.md` §3 B. The literal "break up the htmx updates": serve
the smallest region that changed instead of the whole board. Requires T-0133's
`column:*` events to be useful (without them every column still listens to one
`board` event and refetches everything), and is gated on T-0131 saying board
re-fetches dominate.

## Requirements

- New internal fragment routes, in the same family as `/status` and `/shell`
  (not in the spec's route table, always render the fragment):
  - `GET /p/:id/column/:key?fragment=1` — renders the existing `column` partial;
  - optionally `GET /p/:id/item/:id/card` — renders the existing `item-card`
    partial, for per-card routing.
- Per-column triggers on the board: `hx-trigger="sse:column-:key from:body,
  every 30s"` with `hx-swap="morph"` (T-0129), one per column in
  `templates/partials/board.html`.
- **Fragment parity holds by construction** (§4.3): the same partials, the same
  handlers, rendered standalone or in-page byte-identically — the existing
  `renderFragmentAlways` machinery and the parity test cover it. The DOM
  contract is untouched: columns and cards carry the same testids and
  `data-*` attributes, just in smaller fragments.
- Tests: fragment parity for a column standalone vs in-page; the new trigger
  strings; a column that did not change is not refetched (T-0133's events only
  fire for the changed file).
- If T-0131 says the coarse events are fine, this item stays blocked and is
  cancelled rather than built anyway.
